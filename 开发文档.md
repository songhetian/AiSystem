# 客服质检中台 \- 完整开发文档（可直接落地版）

# 一、文档概述

## 1\.1 文档目的

本文档整合项目所有技术要求与业务规范，明确前后端分离架构下的开发标准、配置流程、核心模块实现细节，涵盖 Ant Design Pro、React Query、Zustand、Prisma、Redis 等核心技术的落地配置，为开发人员提供一站式开发指导，确保项目开发规范、高效、可维护，可直接用于项目初始化与开发落地。

## 1\.2 项目定位

本项目为企业级客服质检中台，核心功能是整合多第三方平台客服数据，实现 AI\+人工双重质检、精细化权限管控、成本均摊统计、多平台API对接等全流程闭环，解决多平台数据分散、质检效率低、权限混乱、成本不可控等核心痛点，采用前后端完全分离架构，保障系统可扩展性与可维护性。

## 1\.3 核心技术栈（强制规范）

### 1\.3\.1 前端技术栈

- 框架：Ant Design Pro v6 \+ Umi 4 \+ @umijs/max

- 状态/请求管理：内置 React Query（TanStack Query v5）\+ Zustand（轻量客户端状态）

- 语言：TypeScript（严格类型校验，禁止随意使用 any 类型）

- UI 组件：Ant Design 5\.x（统一 UI 风格，禁止自定义已有组件）

- 请求工具：@umijs/max 内置 request（Axios 封装）

- 其他：CSS Modules（样式隔离）、@dnd\-kit（拖拽功能）

### 1\.3\.2 后端技术栈

- 框架：NestJS（企业级 Node\.js 框架，推荐）或 Express

- ORM：Prisma（数据库操作，替代传统 ORM，强制使用）

- 缓存：Redis（用于高频数据缓存、会话管理、限流，强制集成）

- 数据库：MySQL 8\.0（关系型数据库，存储核心业务数据）

- 文件存储：MinIO（用于文件上传、下载，对接前端上传组件）

- 鉴权：JWT（用户身份认证，与前端权限系统联动）

# 二、项目整体架构与目录结构

## 2\.1 整体架构（前后端完全分离）

核心原则：前端负责页面展示、交互与接口请求，后端负责接口实现、业务逻辑、数据存储与缓存，两者通过 HTTP/HTTPS 接口通信，完全隔离、独立运行、独立部署，无代码耦合。

架构流程图：前端（Ant Design Pro）→ 接口请求（services）→ 后端（NestJS）→ 数据处理（Prisma\+Redis）→ 数据库/缓存 → 后端响应 → 前端渲染

## 2\.3 目录核心说明（避坑重点）

- frontend/src/services：仅存放前端接口请求函数，不写任何业务逻辑，对应后端 controller 接口，前后端接口地址保持一致。

- frontend/src/store：仅用 Zustand 管理客户端 UI 状态，服务器状态（后端返回数据）由 React Query 管理，两者分工明确，互不冲突。

- backend/prisma：Prisma 核心目录，schema\.prisma 定义数据库模型，migrations 目录自动生成数据库迁移文件，禁止手动修改数据库表。

- backend/src/modules：按前端业务模块拆分，每个模块包含 controller（接口层）、service（业务逻辑层）、dto（数据传输对象），确保前后端模块对应。

# 三、前端开发配置（可直接复制落地）

## 3\.1 启用 React Query（核心配置）

Ant Design Pro（Umi 4）已内置 React Query 插件，只需在 \.umirc\.ts 中开启并配置全局默认参数，无需额外安装依赖。

```typescript
// frontend/.umirc.ts
import { defineConfig } from '@umijs/max';

export default defineConfig({
  // 开启 Umi 内置 React Query 插件（核心）
  plugins: ['@umijs/plugins/dist/react-query'],
  // React Query 全局默认配置（可在组件内单独覆盖）
  reactQuery: {
    defaultOptions: {
      queries: {
        staleTime: 30_000, // 30秒内数据视为新鲜，不重复请求（减少冗余请求）
        refetchOnWindowFocus: false, // 窗口聚焦不自动刷新数据
        retry: 2, // 请求失败自动重试2次
        refetchOnMount: true, // 组件挂载时刷新数据（确保数据最新）
        gcTime: 60_000, // 缓存数据过期时间（1分钟）
      },
    },
  },
  // 开发环境接口代理（解决跨域，对接本地后端服务）
  proxy: {
    '/api': {
      target: 'http://localhost:3000', // 后端服务地址（根据实际修改）
      changeOrigin: true,
      pathRewrite: { '^/api': '' }, // 移除请求路径中的 /api 前缀
    },
  },
  // 其他基础配置（路由、主题等，按实际需求调整）
  routes: [],
  theme: {
    primaryColor: '#1890ff', // Ant Design 主色
  },
});
```

## 3\.2 全局请求拦截配置（app\.tsx）

统一配置请求头（Token 鉴权）、响应拦截（统一解构后端返回格式），与 React Query 协同工作，无需在组件内重复处理。

```typescript
// frontend/src/app.tsx
import { RuntimeConfig } from '@umijs/max';
import { ReactQueryDevtools } from '@tanstack/react-query-devtools';

// 全局请求拦截与响应拦截
export const runtimeConfig: RuntimeConfig = {
  request: {
    baseURL: '/api', // 与 proxy 配置对应
    interceptors: {
      // 请求拦截：自动添加 Token（用户登录后存储在 localStorage）
      request: (config) => {
        const token = localStorage.getItem('token');
        if (token) {
          config.headers.Authorization = `Bearer ${token}`;
        }
        return config;
      },
      // 响应拦截：统一解构后端返回的 { code, message, data } 格式
      response: (response) => {
        const { code, message, data } = response.data;
        // 成功状态（code=200）：直接返回 data，组件中无需再解构
        if (code === 200) {
          return data;
        }
        // 失败状态：抛出错误，React Query 会自动捕获，组件中可处理
        throw new Error(message || '接口请求失败，请重试');
      },
    },
  },
};

// 开发环境注入 React Query DevTools（便于调试缓存、请求状态）
export function rootContainer(container: React.ReactNode) {
  return (
    <>
      {container}
      {process.env.NODE_ENV === 'development' && <ReactQueryDevtools />}
    </>
  );
}
```

## 3\.3 Zustand 状态管理配置（客户端 UI 状态）

针对客服质检中台常见场景，创建全局 Store，管理跨组件共享的 UI 状态，避免 props drilling，简化状态管理。

```typescript
// frontend/src/store/useAppStore.ts
import { create } from 'zustand';

// 定义 Store 类型（严格类型校验，避免类型错误）
interface AppState {
  // 1. 组织架构选中状态（左侧树选中的部门/店铺 ID，联动右侧列表）
  selectedOrgId: string | null;
  setSelectedOrgId: (id: string | null) => void;

  // 2. 批量操作选中项（聊天记录、质检任务等批量选中的 ID 列表）
  selectedIds: string[];
  setSelectedIds: (ids: string[]) => void;
  addSelectedId: (id: string) => void;
  removeSelectedId: (id: string) => void;
  clearSelectedIds: () => void;

  // 3. 质检表单草稿（多步骤质检表单，临时切换页面保留草稿）
  qualityFormDraft: Record<string, any> | null;
  setQualityFormDraft: (draft: Record<string, any> | null) => void;

  // 4. 全局 UI 状态（侧边栏折叠/展开、主题切换等）
  sidebarCollapsed: boolean;
  toggleSidebar: () => void;
}

// 创建 Store，暴露操作方法
export const useAppStore = create<AppState>((set) => ({
  // 组织架构选中状态
  selectedOrgId: null,
  setSelectedOrgId: (id) => set({ selectedOrgId: id }),

  // 批量选中项
  selectedIds: [],
  setSelectedIds: (ids) => set({ selectedIds: ids }),
  addSelectedId: (id) => set((state) => ({
    selectedIds: [...state.selectedIds, id],
  })),
  removeSelectedId: (id) => set((state) => ({
    selectedIds: state.selectedIds.filter((item) => item !== id),
  })),
  clearSelectedIds: () => set({ selectedIds: [] }),

  // 质检表单草稿
  qualityFormDraft: null,
  setQualityFormDraft: (draft) => set({ qualityFormDraft: draft }),

  // 侧边栏状态
  sidebarCollapsed: false,
  toggleSidebar: () => set((state) => ({
    sidebarCollapsed: !state.sidebarCollapsed,
  })),
}));

// frontend/src/store/index.ts（统一导出，便于组件引入）
export { useAppStore } from './useAppStore';
```

## 3\.4 services 接口请求层写法（示例）

services 仅封装接口请求函数，与后端 controller 接口一一对应，统一管理接口地址，组件中通过 React Query 调用，无需直接写 axios 请求。

```typescript
// frontend/src/services/system.ts（系统管理接口示例）
import request from '@/utils/request';

// 定义接口参数和返回值类型（严格类型校验）
export interface UserListParams {
  page: number;
  pageSize: number;
  keyword?: string;
  deptId?: string;
}

export interface UserItem {
  id: string;
  name: string;
  role: string;
  deptId: string;
  createTime: string;
  status: number;
}

// 查询用户列表（GET 请求）
export function getUserList(params: UserListParams) {
  return request('/system/user/list', {
    method: 'GET',
    params,
  });
}

// 新增用户（POST 请求）
export function addUser(data: Omit<UserItem, 'id' | 'createTime'>) {
  return request('/system/user/add', {
    method: 'POST',
    data,
  });
}

// 修改用户（PUT 请求）
export function updateUser(data: UserItem) {
  return request('/system/user/update', {
    method: 'PUT',
    data,
  });
}

// 删除用户（DELETE 请求）
export function deleteUser(id: string) {
  return request(`/system/user/delete/${id}`, {
    method: 'DELETE',
  });
}
```

## 3\.5 组件中使用 React Query \+ Zustand（示例）

组件中通过 React Query 调用接口（管理服务器状态），通过 Zustand 管理 UI 状态，两者协同工作，简化代码，提升可维护性。

```typescript
// frontend/src/pages/System/User/index.tsx（用户列表页面示例）
import { useEffect } from 'react';
import { Table, Button, Input, Space } from 'antd';
import { useQuery, useMutation, useQueryClient } from '@umijs/max';
import { useAppStore } from '@/store';
import { getUserList, deleteUser, UserListParams, UserItem } from '@/services/system';

export default function UserPage() {
  // 1. 用 Zustand 获取全局 UI 状态（批量选中项、组织选中 ID）
  const { selectedIds, setSelectedIds, selectedOrgId } = useAppStore();

  // 2. 用 React Query 调用接口（查询用户列表，自动缓存、重试）
  const queryClient = useQueryClient();
  const [params, setParams] = useState<UserListParams>({
    page: 1,
    pageSize: 10,
    deptId: selectedOrgId || undefined, // 联动组织选中状态
  });

  // 查询用户列表（queryKey 为缓存键，相同 key 复用缓存）
  const { data, loading, error } = useQuery({
    queryKey: ['userList', params], // 缓存键：结合参数，确保缓存精准
    queryFn: () => getUserList(params),
  });

  // 删除用户（mutation 用于增删改操作）
  const deleteMutation = useMutation({
    mutationFn: deleteUser,
    onSuccess: () => {
      // 删除成功后，使 userList 缓存失效，自动重新请求，刷新列表
      queryClient.invalidateQueries({ queryKey: ['userList'] });
      // 清空批量选中项
      setSelectedIds([]);
    },
  });

  // 组织选中状态变化时，更新查询参数，重新请求
  useEffect(() => {
    setParams({ ...params, deptId: selectedOrgId || undefined });
  }, [selectedOrgId]);

  // 表格列配置
  const columns = [
    { title: '用户名', dataIndex: 'name', key: 'name' },
    { title: '角色', dataIndex: 'role', key: 'role' },
    { title: '所属部门', dataIndex: 'deptId', key: 'deptId' },
    { title: '创建时间', dataIndex: 'createTime', key: 'createTime' },
    { title: '操作', key: 'action', render: (_, record) => (
      <Space>
        <Button type="link" onClick={() => {/* 编辑逻辑 */}}>编辑</Button>
        <Button type="link" danger onClick={() => deleteMutation.mutate(record.id)}>删除</Button>
      </Space>
    )},
  ];

  return (
    <Space style={{ marginBottom: 16 }}>
        <Button type="primary">新增用户</Button>
        <Button danger onClick={() => deleteMutation.mutateMany(selectedIds)} disabled={selectedIds.length === 0}>
          批量删除
        </Button>
        <Input placeholder="搜索用户名" onChange={(e) => setParams({ ...params, keyword: e.target.value })} />
      </Space>
      <Table
        columns={columns}
        dataSource={data?.list || []}
        rowKey="id"
        loading={loading}
        pagination={{
          current: params.page,
          pageSize: params.pageSize,
          total: data?.total || 0,
          onChange: (page, pageSize) => setParams({ ...params, page, pageSize }),
        }}
        rowSelection={{
          type: 'checkbox',
          selectedRowKeys: selectedIds,
          onChange: (selectedKeys) => setSelectedIds(selectedKeys as string[]),
        }}
      />

  );
}
```

## 3\.6 前端权限配置（access\.ts）

结合 Ant Design Pro 内置权限系统，定义权限判断逻辑，控制页面、按钮的显示/隐藏，与后端权限联动。

```typescript
// frontend/src/access.ts
import { useAppStore } from '@/store';

// 权限定义：返回权限对象，组件中通过 useAccess 获取
export default function access(initialState: { currentUser?: { roles: string[] } }) {
  const { currentUser } = initialState || {};
  const { selectedOrgId } = useAppStore();

  return {
    // 系统管理员：拥有所有权限
    isAdmin: currentUser?.roles.includes('admin'),
    // 平台管理员：拥有所属平台下的所有权限
    isPlatformAdmin: currentUser?.roles.includes('platformAdmin'),
    // 部门管理员：拥有所属部门下的权限
    isDeptAdmin: currentUser?.roles.includes('deptAdmin'),
    // 查看用户列表权限
    canViewUser: currentUser?.roles.some(role => ['admin', 'platformAdmin', 'deptAdmin'].includes(role)),
```

### 4\.3\.2 Service（业务逻辑层，处理核心业务）

```typescript
// backend/src/modules/system/service/user.service.ts
import { Injectable, NotFoundException } from '@nestjs/common';
import { prisma } from '../../../config/prisma';
import { redis } from '../../../config/redis';
import { QueryUserDto, CreateUserDto } from '../dto/user.dto';
import * as bcrypt from 'bcryptjs'; // 密码加密

@Injectable()
export class UserService {
  // 缓存 key 前缀（避免缓存冲突）
  private readonly CACHE_KEY_PREFIX = 'user:';

  // 查询用户列表（支持分页、筛选，缓存高频查询结果）
  async queryUserList(dto: QueryUserDto) {
    const { page, pageSize, keyword, deptId } = dto;
    const skip = (page - 1) * pageSize;

    // 构建查询条件
    const where: any = {};
    if (keyword) {
      where.OR = [
        { name: { contains: keyword, mode: 'insensitive' } },
        { username: { contains: keyword, mode: 'insensitive' } },
      ];
    }
    if (deptId) {
      where.deptId = deptId;
    }

    // 先查缓存，缓存不存在则查数据库
    const cacheKey = `${this.CACHE_KEY_PREFIX}list:${JSON.stringify(dto)}`;
    const cachedData = await redis.get(cacheKey);
    if (cachedData) {
      return JSON.parse(cachedData);
    }

    // 数据库查询
    const [list, total] = await Promise.all([
      prisma.user.findMany({
        where,
        skip,
        take: pageSize,
        select: {
          id: true,
          name: true,
          username: true,
          roleIds: true,
          deptId: true,
          status: true,
          createTime: true,
        },
        orderBy: { createTime: 'desc' },
      }),
      prisma.user.count({ where }),
    ]);

    // 缓存结果（设置 5 分钟过期，避免数据过时）
    await redis.set(cacheKey, JSON.stringify({ list, total }), 'EX', 300);

    return { list, total };
  }

  // 新增用户（密码加密，新增后清除相关缓存）
  async createUser(dto: CreateUserDto) {
    // 校验用户名是否已存在
    const existUser = await prisma.user.findUnique({
      where: { username: dto.username },
    });
    if (existUser) {
      throw new Error('用户名已存在');
    }

    // 密码加密（bcrypt 加盐加密，前端无需加密）
    const hashedPassword = await bcrypt.hash(dto.password, 10);

    // 新增用户
    const user = await prisma.user.create({
      data: {
        ...dto,
        password: hashedPassword,
      },
    });

    // 清除用户列表缓存（确保缓存数据最新）
    await redis.keys(`${this.CACHE_KEY_PREFIX}list:*`).then(keys => {
      if (keys.length > 0) {
        redis.del(keys);
      }
    });

    return user;
  }

  // 删除用户（删除后清除缓存）
  async deleteUser(id: string) {
    // 校验用户是否存在
    const existUser = await prisma.user.findUnique({ where: { id } });
    if (!existUser) {
      throw new NotFoundException('用户不存在');
    }

    // 删除用户
    await prisma.user.delete({ where: { id } });

    // 清除缓存
    await redis.del(`${this.CACHE_KEY_PREFIX}${id}`);
    await redis.keys(`${this.CACHE_KEY_PREFIX}list:*`).then(keys => {
      if (keys.length > 0) {
        redis.del(keys);
      }
    });

    return { message: '删除成功' };
  }

  // 其他方法（修改用户、查询用户详情等）按业务需求扩展...
}
```

# 五、核心开发规范（强制遵守）

## 5\.1 前端开发规范

- 类型规范：所有变量、函数、组件 Props、接口参数/返回值必须定义 TypeScript 类型，禁止随意使用 any 类型（特殊场景需添加注释说明）。

- 状态管理：服务器状态（后端返回数据）用 React Query 管理，客户端 UI 状态用 Zustand 管理，禁止混用，禁止用 useState 管理跨组件共享状态。

- 组件规范：复用性 ≥ 2 的组件抽离至 components 目录，页面组件内的子组件（仅当前页面复用）放在页面目录下的 components 文件夹，优先使用 Ant Design 组件。

- 接口规范：所有接口统一放在 services 目录，按业务模块拆分，禁止在组件内直接写 axios 请求，接口参数和返回值必须定义类型。

- 样式规范：使用 CSS Modules 实现样式隔离，全局样式放在 assets/styles 目录，禁止使用全局样式污染，禁止使用 \!important（特殊场景需注释说明）。

## 5\.2 后端开发规范

- 数据库规范：所有数据库操作必须通过 Prisma 实现，禁止手动编写 SQL，数据库模型修改后必须生成迁移文件（npx prisma migrate dev）。

- 缓存规范：高频访问、不常变化的数据（用户信息、组织架构、权限列表）必须用 Redis 缓存，设置合理的过期时间，数据修改后必须清除对应缓存。

- 接口规范：接口地址与前端 services 保持一致，请求方式严格遵循 RESTful 规范（GET 查询、POST 新增、PUT 修改、DELETE 删除），统一返回格式。

- 权限规范：所有接口必须启用 JWT 鉴权，敏感接口（新增、修改、删除）必须添加角色权限校验，与前端权限系统联动。

- 异常规范：所有业务异常必须抛出明确的错误信息，全局统一处理异常，返回统一的错误格式，禁止直接返回原生错误。

## 5\.3 前后端交互规范

- 接口地址：前端请求地址统一前缀 /api，后端接口地址与前端 services 一一对应，如前端 getUserList 对应后端 /system/user/list。

- 返回格式：后端所有接口统一返回 \{ code: number, message: string, data: any \}，code=200 为成功，其他为失败，前端通过响应拦截自动解构。

- 鉴权方式：前端登录后获取 JWT Token，存储在 localStorage，请求时通过请求拦截自动添加到请求头，后端通过 JWT 守卫校验 Token。

- 数据格式：前后端数据格式保持一致，日期格式统一为 ISO 格式（YYYY\-MM\-DD HH:mm:ss），分页参数统一为 page、pageSize，返回分页数据包含 list、total。

# 七、常见问题与避坑指南

- 前端跨域问题：确保 \.umirc\.ts 中的 proxy 配置与后端服务地址一致，后端启用 CORS，重启前后端服务即可解决。

- React Query 缓存不更新：确保 queryKey 与参数对应，数据修改后调用 invalidateQueries 清除对应缓存。

- Zustand 状态不生效：检查组件是否正确引入 useAppStore，是否使用 set 方法修改状态（禁止直接修改状态）。

- Prisma 迁移失败：检查数据库连接是否正常，schema\.prisma 语法是否正确，删除 migrations 目录重新执行 migrate dev。

- Redis 缓存冲突：给缓存 key 添加统一前缀，避免不同模块的缓存 key 重复。

以上为客服质检中台开发过程中高频出现的问题及解决方案，开发人员在实际落地过程中，可结合具体业务场景灵活调整，若遇到上述未覆盖的问题，可优先检查前后端配置一致性、技术栈版本兼容性及规范执行情况，确保项目开发高效推进、顺利落地。

```
import { prisma } from '../../../config/prisma';
import { redis } from '../../../config/redis';
import { QueryRoleDto, CreateRoleDto, AssignPermissionDto } from '../dto/role.dto';

@Injectable()
export class RoleService {
  private readonly CACHE_KEY_PREFIX = 'role:';

  // 查询角色列表
  async queryRoleList(dto: QueryRoleDto) {
    const { page, pageSize, keyword } = dto;
    const skip = (page - 1) * pageSize;
    const where: any = {};

    if (keyword) {

    });
    if (existRole) throw new Error('角色名称或编码已存在');

    const role = await prisma.role.create({ data: dto });
    await this.clearRoleCache();
    return role;
  }

  // 分配角色权限
  async assignPermission(dto: AssignPermissionDto) {
    const { roleId, permissionIds } = dto;
    const existRole = await prisma.role.findUnique({ where: { id: roleId } });
    if (!existRole) throw new NotFoundException('角色不存在');

    // 权限分配逻辑（需先创建permission表，存储系统权限项）
    const rolePermission = await prisma.rolePermission.upsert({
      where: { roleId },
      update: { permissionIds },
      create: { roleId, permissionIds },
    });

    // 清除对应用户的权限缓存
    await redis.keys(`user:permission:${roleId}:*`).then(keys => {
      if (keys.length > 0) redis.del(keys);
    });
    await this.clearRoleCache();
    return rolePermission;
  }

  // 清除角色缓存
  private async clearRoleCache() {
    const keys = await redis.keys(`${this.CACHE_KEY_PREFIX}*`);
    if (keys.length > 0) await redis.del(keys);
  }
}
```

```typescript
import { Injectable } from '@nestjs/common';
import { prisma } from '../../../config/prisma';
import { redis } from '../../../config/redis';

@Injectable()
export class AiQualityService {
  private readonly CACHE_KEY_PREFIX = 'aiQuality:';

  // 查询AI质检任务列表
  async queryTaskList(dto: QueryAiQualityTaskDto) {
    const { page, pageSize, platformId, status } = dto;
    const skip = (page - 1) * pageSize;
    const where: any = {};
    if (platformId) where.platformId = platformId;
    if (status !== undefined) where.status = status;

    const cacheKey = `${this.CACHE_KEY_PREFIX}taskList:${JSON.stringify(dto)}`;
    const cachedData = await redis.get(cacheKey);
    if (cachedData) return JSON.parse(cachedData);

    const [list, total] = await Promise.all([
      prisma.aiQualityTask.findMany({ where, skip, take: pageSize, orderBy: { createTime: 'desc' } }),
      prisma.aiQualityTask.count({ where }),
    ]);

    await redis.set(cacheKey, JSON.stringify({ list, total }), 'EX', 60);
    return { list, total };
  }

  // 创建AI质检任务
  async createTask(dto: CreateAiQualityTaskDto) {
    const task = await prisma.aiQualityTask.create({ data: dto });
    await this.clearTaskCache();
    // 触发异步质检任务（对接AI平台）
    this.executeAiQualityTask(task.id);
    return task;
  }

  // 异步执行AI质检（核心业务逻辑）
  private async executeAiQualityTask(taskId: string) {
    // 1. 更新任务状态为执行中
    await prisma.aiQualityTask.update({
      where: { id: taskId },
      data: { status: 1, executeTime: new Date() },
    });

    try {
      // 2. 拉取对应聊天记录
      // 3. 调用AI平台接口执行质检规则
      // 4. 生成质检结果，关联违规标签
      // 5. 更新任务状态为已完成
      await prisma.aiQualityTask.update({
        where: { id: taskId },
        data: { status: 2, finishTime: new Date() },
      });
    } catch (error) {
      // 执行失败，更新状态，记录错误
      await prisma.aiQualityTask.update({
        where: { id: taskId },
        data: { status: 3 },
      });
    } finally {
      await this.clearTaskCache();
    }
  }

  private async clearTaskCache() {
    const keys = await redis.keys(`${this.CACHE_KEY_PREFIX}*`);
    if (keys.length > 0) await redis.del(keys);
  }
```

```typescript
import { ExceptionFilter, Catch, ArgumentsHost, HttpException, HttpStatus } from '@nestjs/common';
import { Response } from 'express';
import { error } from './response';

@Catch()
export class AllExceptionFilter implements ExceptionFilter {
  catch(exception: any, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const response = ctx.getResponse<Response>();

    // HTTP异常处理
    if (exception instanceof HttpException) {
      const status = exception.getStatus();
      const exceptionResponse = exception.getResponse();
      const message = typeof exceptionResponse === 'string'
        ? exceptionResponse
        : (exceptionResponse as any).message || exception.message;

      response.status(status).json(error(message, status));
      return;
    }

    // 系统异常处理
    console.error('系统异常：', exception);
    response.status(HttpStatus.INTERNAL_SERVER_ERROR).json(
      error(exception.message || '服务器内部错误', HttpStatus.INTERNAL_SERVER_ERROR)
    );
  }
}
```

## 9.4 角色权限守卫

**backend/src/guards/roles.guard.ts**

```
import { Injectable, CanActivate, ExecutionContext } from '@nestjs/common';
import { Reflector } from '@nestjs/core';
import { prisma } from '../config/prisma';
import { redis } from '../config/redis';

@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private reflector: Reflector) {}

  async canActivate(context: ExecutionContext): Promise<boolean> {
    // 获取接口要求的角色
    const requiredRoles = this.reflector.get<string[]>('roles', context.getHandler());
    if (!requiredRoles || requiredRoles.length === 0) return true;

    // 获取当前登录用户
    const request = context.switchToHttp().getRequest();
    const user = request.user;
    if (!user) return false;

    // 从缓存获取用户角色权限
    const cacheKey = `user:permission:${user.id}`;
    let userRoles = await redis.get(cacheKey);

    if (!userRoles) {
      // 缓存不存在，从数据库查询
      const roles = await prisma.role.findMany({
        where: { id: { in: user.roleIds } },
        select: { code: true },
      });
      userRoles = roles.map(item => item.code);
      // 缓存1小时
      await redis.set(cacheKey, JSON.stringify(userRoles), 'EX', 3600);
    } else {
      userRoles = JSON.parse(userRoles);
    }

    // 校验角色是否匹配
    return requiredRoles.some(role => userRoles.includes(role));
  }
}
```

# 十二、测试规范

## 12.1 前端测试规范

1. **单元测试**：使用 Jest + React Testing Library，对公共组件、工具函数、Hooks 编写单元测试，核心代码覆盖率≥80%
2. **E2E 测试**：使用 Cypress，对核心业务流程（登录、用户管理、质检任务创建）编写端到端测试，确保主流程正常
3. **兼容性测试**：必须兼容 Chrome、Edge 最新版，适配 1920*1080、1366*768 等主流分辨率
4. **性能测试**：首屏加载时间≤3s，页面切换无卡顿，接口请求响应时间≤1s

## 12.2 后端测试规范

1. **单元测试**：使用 Jest，对 Service 层核心业务逻辑编写单元测试，核心代码覆盖率≥85%
2. **接口测试**：使用 Postman/Swagger，对所有接口进行功能测试，确保入参校验、权限校验、异常处理正常
3. **性能测试**：使用 JMeter，对核心接口进行压测，单接口 QPS≥100，响应时间≤500ms
4. **安全测试**：对所有接口进行 SQL 注入、XSS、越权访问测试，确保无安全漏洞

# 十三、安全规范

## 13.1 前端安全规范

1. 禁止在前端存储敏感信息（如密钥、密码），Token 仅存储在 localStorage/sessionStorage
2. 所有用户输入必须进行 XSS 过滤，禁止直接渲染用户输入的 HTML 内容
3. 所有表单必须添加参数校验，禁止非法参数提交
4. 生产环境禁止开启控制台调试，禁止暴露接口地址、业务逻辑等敏感信息

## 13.2 后端安全规范

1. 所有接口必须添加 JWT 鉴权，敏感接口必须添加角色权限校验，防止越权访问
2. 所有用户输入必须进行参数校验，禁止直接拼接 SQL，防止 SQL 注入
3. 密码必须使用 bcrypt 加盐加密存储，禁止明文存储
4. 敏感接口必须添加限流措施，防止恶意攻击
5. 所有异常必须统一处理，禁止暴露服务器路径、数据库结构等敏感信息
6. 定期更新依赖版本，修复安全漏洞

# 十四、项目迭代与维护规范

# 十五、你必须记住的 **3 个 “统一样式” 标签**

只要你的页面**套上这 3 层**，**自动和系统一模一样**，不用写 CSS！

```tsx
// 1. 最外层：页面容器（带标题、面包屑、 margins 间距）
<PageContainer>

  // 2. 第二层：卡片（带阴影、内边距、背景）
  <Card>

    // 3. 第三层：你的内容（表格、表单、按钮）
    <Table />
    <Form />

  </Card>
</PageContainer>
```

### 只要这样写 → 页面**100% 和系统统一**！

不写 → 页面就会**难看、贴边、没间距、风格混乱**！

# 十六、这三个标签是干嘛的？（你必须知道）

## 1. `<PageContainer>`

- 带**页面标题**
- 带**面包屑导航**
- 带**标准外边距**
- 保持所有页面**上下左右间距一致**

## 2. `<Card>`

- 带**白色背景**
- 带**柔和阴影**
- 带**内边距（内间距）**
- 让内容不贴边，看起来很专业

## 3. 里面放官方组件：Table / Form / Button / Input

- **官方自带样式**
- 颜色、字体、大小全部统一

- 没有背景、没有阴影
- 字体、间距乱七八糟
- **就是你之前觉得 “写出来很难看” 的原因！**
