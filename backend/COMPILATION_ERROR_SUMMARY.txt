【问题 1】Prisma 类型错误 (83% 的错误)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  原因: Prisma schema 定义与生成的类型不一致
  影响: 数据库操作、类型定义

  常见错误:
    • Type 'JsonValue' is not assignable to type 'JsonNull | InputJsonValue'
    • Property 'where' does not exist on type 'attendance_leaveCreateArgs'
    • Type 'PaginatedResponse<any>' has no matching index signature

  修复方案:
    1. 重新生成 Prisma 客户端: npx prisma generate
    2. 检查 schema.prisma 中的字段定义
    3. 更新 Prisma 版本: npm update @prisma/client

  预期效果: 减少 ~800 个错误 (71%)

【问题 2】装饰器参数错误 (4.3% 的错误)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  原因: 装饰器接口定义与实际使用不符
  影响: @RateLimit, @Cache, @CacheEvict 装饰器

  具体问题:
    • @RateLimit 缺少 'type' 属性 (30 处)
    • @Cache 中 'key' 属性不存在 (8 处)
    • @CacheEvict 中 'keys' 属性不存在 (10 处)

  受影响文件:
    • src/modules/service/controllers/service.controller.ts
    • src/modules/system/controllers/system-menus.controller.ts
    • src/modules/system/controllers/system-roles.controller.ts
    • src/modules/system/controllers/system-users.controller.ts

  修复方案:
    方案 A: 在每个装饰器中添加缺失的属性
      @RateLimit({ type: 'ip', limit: 30, window: 60 })

    方案 B: 更新装饰器定义，使属性可选
      export interface RateLimitOptions {
        type?: RateLimitType;  // 改为可选
        limit: number;
        window: number;
      }

  预期效果: 减少 ~48 个错误 (4.3%)

【问题 3】模块导入错误 (0.7% 的错误)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  预期效果: 减少 ~8 个错误 (0.7%)

【问题 4】错误处理中的类型问题 (1.6% 的错误)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  原因: TypeScript strict mode 下 error 类型为 unknown
  影响: catch 块中的错误处理

  常见错误:
    • 'error' is of type 'unknown'
    • Cannot access error.message

  受影响文件:
    • src/modules/system/services/archive.service.ts
    • src/modules/system/services/mapping.service.ts
    • src/modules/system/services/permission-cleanup.service.ts
    • src/modules/system/services/permission-template.service.ts
    • src/modules/system/services/system-logs.service.ts
    • src/modules/system/workers/cron.worker.ts

  修复方案:
    方案 A: 类型断言
      catch (error) {
        this.logger.error(`Error: ${(error as Error).message}`);
      }

    方案 B: 类型守卫
      catch (error) {
        const message = error instanceof Error ? error.message : String(error);
        this.logger.error(`Error: ${message}`);
      }

  预期效果: 减少 ~12 个错误 (1.1%)

【问题 5】方法签名不匹配 (1.3% 的错误)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  原因: 方法定义与调用处的参数不一致
  影响: findAll(), sort() 等方法

  常见错误:

    • Property 'sort' does not exist on type 'SystemDepartmentsService'

  受影响文件:
    • src/modules/system/services/system-departments.service.ts
    • src/modules/system/services/system-menus.service.ts
    • src/modules/shop/services/product.service.ts

  修复方案:
    1. 检查方法定义和调用处的参数
    2. 完成未完成的方法实现
    3. 统一参数定义

  预期效果: 减少 ~15 个错误 (1.3%)
