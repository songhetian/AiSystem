# 登录问题排查指南

## 问题描述

用户访问 `/system/users` 时，请求头中没有 `Authorization` token，导致无法访问受保护的接口。

## 排查步骤

### 1. 检查localStorage中是否有token

打开浏览器开发者工具：
1. 按 `F12` 打开开发者工具
2. 切换到 `Application` 标签
3. 左侧菜单选择 `Local Storage` → `http://localhost:8000`
4. 查看是否有以下两个key：
   - `token` - JWT Token
   - `currentUser` - 用户信息

**预期结果**：
- `token`: 应该是一个长字符串（JWT格式）
- `currentUser`: 应该是一个JSON字符串，包含用户信息

**如果没有这两个key**：
- 说明用户没有登录，或者登录后token没有正确保存
- 需要重新登录

---

### 2. 检查是否已登录

在浏览器控制台（Console）中执行：

```javascript
// 检查token
console.log('Token:', localStorage.getItem('token'));

// 检查用户信息
console.log('User:', localStorage.getItem('currentUser'));

// 检查是否已登录
console.log('Is Authenticated:', !!localStorage.getItem('token'));
```

**预期结果**：
- Token应该存在且不为null
- User应该存在且不为null
- Is Authenticated应该为true

---

### 3. 重新登录

如果localStorage中没有token，请按以下步骤重新登录：

1. 访问登录页面：`http://localhost:8000/login`
2. 输入用户名：`admin`
3. 输入密码：`Admin123456`
4. 点击"进入系统"按钮
5. 等待登录成功，自动跳转到首页

**登录成功后，再次检查localStorage**：
```javascript
console.log('Token:', localStorage.getItem('token'));
console.log('User:', localStorage.getItem('currentUser'));
```

### 4. 检查登录接口是否正常

**请求**：

### 5. 检查请求拦截器是否正常工作

登录成功后，访问任意业务接口（如：`/system/users`），在Network标签中查看请求头：

**预期请求头**：
```
GET /api/v1/system/users HTTP/1.1
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
Content-Type: application/json
```

**如果请求头中没有Authorization**：
- 说明请求拦截器没有正常工作
- 检查 `frontend/src/utils/request.ts` 中的请求拦截器逻辑

---

### 6. 手动添加token到请求头（临时测试）

如果请求拦截器有问题，可以手动添加token到请求头进行测试：

在浏览器控制台中执行：

```javascript
// 获取token
const token = localStorage.getItem('token');

// 手动发送请求
fetch('http://localhost:3000/api/v1/system/users', {
  method: 'GET',
  headers: {
    'Authorization': `Bearer ${token}`,
    'Content-Type': 'application/json'
  }
})
.then(response => response.json())
.then(data => console.log('Response:', data))
.catch(error => console.error('Error:', error));
```

**预期结果**：
- 应该返回用户列表数据
- 如果返回401错误，说明token无效或已过期

### 7. 检查token是否有效

在浏览器控制台中执行：

```javascript
// 获取token
const token = localStorage.getItem('token');

// 解析token（JWT格式）
function parseJwt(token) {
  try {
    const base64Url = token.split('.')[1];
    const base64 = base64Url.replace(/-/g, '+').replace(/_/g, '/');
    const jsonPayload = decodeURIComponent(atob(base64).split('').map(function(c) {
      return '%' + ('00' + c.charCodeAt(0).toString(16)).slice(-2);
    }).join(''));
    return JSON.parse(jsonPayload);
  } catch (e) {
    return null;
  }
}

// 解析并检查token
const payload = parseJwt(token);
console.log('Token Payload:', payload);

// 检查是否过期
if (payload && payload.exp) {
  const expirationDate = new Date(payload.exp * 1000);
  const now = new Date();
  console.log('Token过期时间:', expirationDate);
  console.log('当前时间:', now);
  console.log('是否已过期:', now > expirationDate);
}
```

**预期结果**：
- Token Payload应该包含用户信息（sub, username, platform_id等）
- Token应该未过期

### 8. 清除缓存并重新登录

如果以上步骤都无法解决问题，尝试清除所有缓存并重新登录：

```javascript
// 清除所有localStorage
localStorage.clear();

// 清除所有sessionStorage
sessionStorage.clear();

// 刷新页面
window.location.reload();
```

然后重新登录。

## 常见问题

### Q1: 登录成功但token没有保存到localStorage

**原因**：
- 登录接口返回的数据格式不正确
- `handleLoginSuccess` 函数没有正确执行

**解决方法**：
1. 检查登录接口的响应格式
2. 在登录页面的 `onSuccess` 回调中添加日志：

```typescript
onSuccess: (data) => {
  console.log('[Login] 登录响应:', data);
  console.log('[Login] Token:', data.access_token || data.accessToken);
  console.log('[Login] User:', data.user);

  // 使用auth工具类保存Token和用户信息
  handleLoginSuccess(data);

  // 验证是否保存成功
  console.log('[Login] localStorage Token:', localStorage.getItem('token'));
  console.log('[Login] localStorage User:', localStorage.getItem('currentUser'));

  // ...
}
```

---

### Q2: Token保存成功但请求头中没有Authorization

**原因**：
- 请求拦截器没有正常工作
- 请求配置中设置了 `skipAuth: true`

**解决方法**：
1. 检查 `frontend/src/utils/request.ts` 中的请求拦截器
2. 确保请求配置中没有设置 `skipAuth: true`
3. 在请求拦截器中添加日志：

```typescript
instance.interceptors.request.use(
  (config: any) => {
    console.log('[Request] 请求配置:', config);
    console.log('[Request] skipAuth:', config.skipAuth);

    // 1. 添加Token
    if (!config.skipAuth) {
      const token = localStorage.getItem("token");
      console.log('[Request] Token:', token);

      if (token) {
        const authHeader = `Bearer ${token}`;
        config.headers.Authorization = authHeader;
        console.log('[Request] Authorization:', authHeader);
      }
    }

    return config;
  },
  // ...
);
```

---

### Q3: Token有效但后端返回401错误

**原因**：
- Token已加入黑名单
- Token签名验证失败
- JWT密钥不匹配

**解决方法**：
1. 检查后端日志，查看具体的错误信息
2. 检查 `.env` 文件中的 `JWT_SECRET` 配置
3. 重新登录获取新的token

---

### Q4: 页面刷新后token丢失

**原因**：
- localStorage被清除
- 浏览器隐私模式

**解决方法**：
1. 检查是否使用了浏览器的隐私模式（无痕模式）
2. 检查是否有其他脚本清除了localStorage
3. 使用普通模式打开浏览器

## 快速修复脚本

如果你确定后端服务正常，但前端无法正常登录，可以尝试以下快速修复脚本：

```javascript
// 1. 清除所有缓存
localStorage.clear();
sessionStorage.clear();

// 2. 手动登录（替换为实际的API地址）
fetch('http://localhost:3000/api/v1/auth/login', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    username: 'admin',
    password: 'Admin123456'
  })
})
.then(response => response.json())
.then(data => {
  console.log('登录响应:', data);

  if (data.code === 200 && data.data) {
    // 保存token
    const token = data.data.access_token || data.data.accessToken;
    localStorage.setItem('token', token);
    console.log('Token已保存:', token);

    // 保存用户信息
    localStorage.setItem('currentUser', JSON.stringify(data.data.user));
    console.log('用户信息已保存:', data.data.user);

    // 刷新页面
    window.location.href = '/';
  } else {
    console.error('登录失败:', data.message);
  }
})
.catch(error => {
  console.error('登录错误:', error);
});
```
