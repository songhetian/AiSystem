# 文件上传至MinIO并导入Qdrant及知识库管理页面需求文档

# 一、需求概述

本次需求旨在开发一套集文件上传、MinIO存储、Qdrant向量导入、知识库管理及豆包式聊天功能于一体的页面系统，支持图片、Excel、PPT、Word、PDF等多类型文件的全流程处理，其中知识库页面及聊天功能均需遵循豆包产品的设计风格（简洁、清晰、易用、轻量化，突出内容可读性，交互流畅且符合用户使用习惯）。系统核心目标是实现文件的便捷上传、安全存储、高效解析及向量化导入，同时通过豆包风格的知识库页面实现数据管理，借助豆包式聊天功能实现基于知识库内容的智能问答，提升操作效率和使用体验。

核心范围：文件上传模块（多类型支持）、MinIO存储集成、Qdrant向量导入模块、知识库管理页面（豆包风格）、豆包式聊天功能、异常处理。

# 二、整体设计原则

## 2.1 功能原则

- 完整性：覆盖文件上传、存储、解析、向量导入、知识库管理、豆包式聊天全流程，无功能断点；

- 兼容性：支持图片（JPG、PNG、GIF、BMP等）、Excel（XLS、XLSX）、PPT（PPT、PPTX）、Word（DOC、DOCX）、PDF等主流文件格式，适配不同大小、不同编码的文件；聊天功能支持多轮对话、文本+文件关联问答，适配不同交互场景；

- 高效性：文件上传、解析、向量导入过程流畅，无明显卡顿，大文件支持断点续传，导入进度可实时查看；聊天问答响应迅速，无明显延迟，上下文衔接流畅；

- 安全性：文件存储符合MinIO安全规范，防止文件泄露；向量导入过程中保证数据完整性，避免数据丢失或错乱；聊天内容仅本地缓存，保障用户隐私。

## 2.2 设计风格原则（豆包风格，含聊天功能）

- 简洁清爽：页面布局清晰，无多余冗余元素，配色以浅色系（白色、浅灰、淡蓝）为主，突出内容本身，避免复杂装饰；聊天窗口简洁干净，区分用户与系统消息，无多余广告或冗余组件；

- 易用性：交互逻辑简单直观，操作步骤清晰，按钮、菜单布局合理，符合用户常规使用习惯，无需复杂学习成本；聊天功能支持一键发送、回车发送，问答流程简单，支持上下文记忆，无需重复输入背景信息；

- 轻量化：页面加载速度快，避免 heavy 组件，支持快速切换、搜索、筛选，提升操作流畅度；聊天窗口可折叠、可展开，不占用核心操作空间，不影响文件上传、知识库管理等核心操作；

- 一致性：页面字体、按钮样式、间距、弹窗风格统一，聊天窗口样式、消息气泡、加载动画与豆包现有产品视觉风格保持一致，提升用户熟悉度；

- 可读性：知识库内容、聊天消息排版规整，文件信息、向量数据、问答内容展示清晰，支持字体大小调整、明暗模式切换，适配不同使用场景；聊天消息区分清晰，用户消息与系统回复视觉差异明显，便于阅读。

# 三、核心功能需求

## 3.1 文件上传模块

### 3.1.1 多类型文件支持

- 支持文件类型：图片（JPG、PNG、GIF、BMP、TIFF）、Excel（XLS、XLSX）、PPT（PPT、PPTX）、Word（DOC、DOCX）、PDF，后续可扩展其他主流文件格式；

- 文件大小限制：单个文件最大支持100MB，支持多文件同时上传（最多可同时选择10个文件）；

- 文件校验：上传前自动校验文件格式、大小，不符合要求的文件提示用户（例：“请上传PDF、Word等支持的文件格式”“文件大小不能超过100MB”），且无法上传。

### 3.1.2 上传操作功能

- 上传方式：支持点击上传（点击上传按钮选择本地文件）、拖拽上传（将本地文件拖拽至上传区域，显示拖拽提示）；

- 断点续传：大文件（超过10MB）支持断点续传，关闭页面或刷新后，重新上传可继续上次进度，无需重新上传整个文件；

- 上传进度展示：每个文件上传时显示实时进度条（百分比），支持暂停、取消上传，暂停后可恢复上传，取消上传后清除已上传部分；

- 上传状态提示：上传成功、上传失败、暂停、取消等状态，均有明确的文字提示（例：“文件上传成功”“上传失败，请检查网络后重试”），失败时提供重试按钮；

- 文件命名规则：上传文件可保留原文件名，若存在同名文件，自动在文件名后添加“(1)”“(2)”等后缀，避免文件覆盖；用户也可手动修改上传后的文件名（上传前/上传后均可）。

## 3.2 MinIO存储集成

- 存储配置：系统自动对接MinIO服务，无需用户手动配置，确保文件上传后实时同步至MinIO指定桶（bucket），桶的命名规范为“knowledge-base-xxx”（xxx为系统标识）；

- 文件存储：文件按类型分类存储（例：images/、excel/、ppt/、word/、pdf/），便于后续管理和查询；存储的文件保留原始格式和属性，支持预览（部分文件类型）；

- 文件访问：所有上传的文件均可直接预览、下载、删除，无需权限验证，操作便捷，贴合轻量化使用需求；

- 文件备份：上传至MinIO的文件自动进行备份，防止文件丢失，备份策略为实时备份（上传成功即同步备份），备份文件保留时间可配置（默认保留30天）。

## 3.3 Qdrant向量导入模块

### 3.3.1 文件解析

- 解析支持：对上传至MinIO的文件进行自动解析，提取文件核心内容（文本、图片特征等），不同文件类型解析规则如下：
      

- 文本类文件（Word、Excel、PDF）：解析文件中的文字内容，去除格式冗余（如页码、页眉页脚、空白行），提取有效文本；Excel文件支持解析所有工作表内容，按行/列整理文本；

- 图片类文件：解析图片的视觉特征（如颜色、纹理、轮廓），转换为可用于向量生成的特征数据；

- PPT文件：解析每一页的文字内容、图片内容，整合为整体文本+图片特征数据，支持按页面拆分解析。

解析进度：解析过程实时显示进度（百分比），解析完成后提示“文件解析成功，可导入Qdrant”，解析失败提示失败原因（例：“文件损坏，无法解析”“不支持的文件格式”），并提供重新解析按钮；

解析结果预览：解析完成后，用户可预览解析后的内容（文本可直接查看，图片可查看特征提取预览图），确认无误后再进行向量导入。

### 3.3.2 向量导入

- 导入触发：支持手动导入（解析完成后，用户点击“导入Qdrant”按钮触发）、自动导入（用户可设置“解析完成后自动导入Qdrant”，默认关闭）；

- 向量生成：解析后的内容（文本、图片特征）自动转换为向量数据，向量维度可配置（默认1024维），生成过程后台运行，不影响用户其他操作；

- Qdrant对接：系统自动对接Qdrant服务，向量数据导入至指定的Qdrant集合（collection），集合命名规范与MinIO桶对应，便于关联查询；

- 导入进度与状态：导入过程显示实时进度条，导入成功后提示“向量导入Qdrant成功”，并关联MinIO文件ID与Qdrant向量ID，便于后续查询；导入失败提示失败原因（例：“Qdrant服务异常”“向量生成失败”），支持重试；

- 向量数据关联：导入后的向量数据与原始文件、解析内容关联，可通过向量ID查询对应的原始文件、解析内容，也可通过原始文件查询对应的向量数据，为聊天问答提供数据支撑。

## 3.4 知识库管理页面（豆包风格）

### 3.4.1 页面布局

- 顶部导航栏：左侧显示系统名称/Logo（与豆包风格一致），中间显示搜索框，右侧显示明暗模式切换、帮助按钮，导航栏简洁，无多余元素；

- 左侧侧边栏：分为“文件管理”“知识库列表”“向量管理”三个模块，默认选中“知识库列表”，侧边栏可折叠（折叠后仅显示图标），配色与豆包侧边栏一致；

- 主内容区：默认显示知识库列表，布局简洁，内容居中，间距合理，背景为白色，字体为无衬线字体（与豆包一致），支持明暗模式切换；

- 底部状态栏：显示当前操作状态、系统版本、联系客服等信息，字体较小，不占用核心视觉空间；

- 聊天入口：页面右下角设置固定豆包式聊天入口（图标+“豆包”文字），点击可展开聊天窗口，收起后仅显示图标，不影响其他操作。

### 3.4.2 核心功能模块（知识库页面）

#### （1）知识库列表

- 列表展示：以卡片/列表形式展示所有已导入Qdrant的知识库条目，每个条目包含：知识库名称（默认以原始文件名命名，可修改）、文件类型（图标+文字提示）、文件大小、上传时间、导入时间、解析状态、向量导入状态、操作按钮；

- 筛选功能：支持按文件类型（下拉选择：全部、图片、Excel、PPT、Word、PDF）、上传时间（日期范围选择）、导入状态（全部、未导入、导入成功、导入失败）筛选，筛选条件可组合使用；

- 搜索功能：支持搜索知识库名称、原始文件名，搜索实时匹配，输入关键词后立即显示符合条件的条目，支持模糊搜索；

- 排序功能：支持按上传时间、导入时间、文件大小排序（升序/降序），默认按上传时间降序排列；

- 操作按钮：每个条目包含“查看详情”“预览文件”“查看向量”“编辑名称”“删除”按钮，按钮样式简洁，hover时显示提示，与豆包按钮风格一致；

- 批量操作：支持勾选多个知识库条目，进行批量删除、批量重新导入向量操作，批量操作按钮位于列表顶部，默认隐藏，勾选条目后显示。

#### （2）文件管理

- 展示所有上传至MinIO的文件（包括未解析、未导入向量的文件），列表形式展示，包含文件名、文件类型、文件大小、上传时间、存储路径、解析状态、操作按钮；

- 操作功能：支持预览文件（文本类可直接查看，图片类可预览原图，Excel/PPT/Word/PDF可预览解析后的内容）、下载文件、删除文件、重新解析、导入Qdrant；

- 筛选与搜索：与知识库列表筛选、搜索规则一致，支持按文件类型、上传时间、解析状态筛选，支持搜索文件名。

#### （3）向量管理

- 展示所有导入Qdrant的向量数据，包含向量ID、关联文件名称、向量维度、导入时间、操作按钮；

- 操作功能：支持查看向量详情（向量数值、关联文件、解析内容）、删除向量（删除后不影响原始文件，仅删除Qdrant中的向量数据）、重新生成向量；

- 筛选与搜索：支持按向量维度、导入时间筛选，支持搜索向量ID、关联文件名称。

#### （4）详情页

- 知识库详情：点击“查看详情”进入，展示知识库完整信息，包括：原始文件信息（文件名、类型、大小、上传时间、存储路径）、解析内容（文本/图片特征预览）、向量信息（向量ID、维度、导入时间）、操作记录（上传、解析、导入的时间及状态）；

- 页面交互：详情页支持返回列表、编辑知识库名称、删除知识库（删除后同时删除MinIO中的文件和Qdrant中的向量数据）、重新解析、重新导入向量，按钮布局简洁，操作便捷；

- 预览体验：文本类解析内容支持复制、字体大小调整，图片类支持放大预览、下载，Excel/PPT/Word/PDF支持分页预览。

### 3.4.3 豆包风格细节要求

- 配色：主色为淡蓝（与豆包一致），辅助色为浅灰、白色，强调色（按钮、提示）为蓝色，避免鲜艳刺眼的颜色，整体色调柔和；

- 字体：正文使用14px无衬线字体，标题使用16-18px加粗字体，间距合理，行高1.5，确保可读性；

- 按钮：圆角按钮（圆角半径4px），默认状态为浅灰，hover状态为淡蓝，点击状态为深蓝，无边框或细边框，按钮文字简洁（如“查看”“删除”“导入”）；

- 弹窗：弹窗居中显示，圆角设计，标题简洁，内容清晰，按钮布局在弹窗底部（确认/取消），弹窗背景有半透明遮罩，避免干扰用户视线；

- 加载状态：使用豆包风格的加载动画（简洁的旋转图标），加载时显示“加载中...”提示，加载完成后自动消失，避免长时间无反馈；

- 提示信息：成功、失败、警告等提示，使用豆包风格的提示框（轻量、简洁），显示在页面顶部或中间，3-5秒后自动消失，不占用核心操作空间。

## 3.5 豆包式聊天功能（核心新增）

### 3.5.1 聊天窗口布局（贴合豆包风格）

- 窗口样式：固定在页面右下角，默认收起（仅显示豆包图标+“豆包”文字），点击后展开，展开后为长方形窗口（宽380px，高500px），可拖动位置、可最小化、可关闭，关闭后恢复为底部图标；

- 顶部栏：窗口顶部显示“豆包”Logo+文字，右侧设置最小化、关闭按钮，样式与豆包聊天窗口一致，简洁无冗余；

- 聊天内容区：占据窗口主体，背景为浅灰色（与豆包一致），消息按时间顺序排列，用户消息居右（气泡为淡蓝色，文字为黑色），系统回复居左（气泡为白色，文字为黑色），消息间距合理，支持上下滚动查看历史对话；

- 输入区：窗口底部为输入框+发送按钮，输入框支持多行输入，提示文字为“请输入你的问题（可询问知识库相关内容）”，发送按钮为圆角蓝色，显示“发送”文字，同时支持回车发送；输入框右侧可添加“清空对话”小按钮，便于快速重置聊天记录。

### 3.5.2 核心聊天功能（贴合豆包交互逻辑）

- 基础问答：用户可输入文本问题，系统基于已导入Qdrant的知识库向量数据，检索相关内容并生成简洁、准确的回答，回答风格贴合豆包（亲切、易懂，避免专业术语堆砌），支持文本、短句、段落式回答；

- 上下文记忆：支持多轮对话，系统自动记忆当前会话的历史提问和回答，用户后续提问无需重复背景信息，上下文衔接流畅，符合豆包多轮对话逻辑，会话记忆仅在当前页面有效，刷新页面后清空历史对话；

- 知识库关联问答：可直接询问特定文件、知识库的相关内容（例：“查看PDF文件的解析内容”“这个Excel文件的向量维度是多少”），系统自动关联MinIO文件、Qdrant向量数据，精准返回对应信息，支持模糊查询；

- 操作引导：用户首次点击聊天窗口，弹出豆包式引导气泡（轻量、简洁），提示“你可以询问知识库相关问题，例如‘查看已导入的PDF文件’”，引导用户快速上手；

- 消息状态反馈：发送消息后，显示豆包风格加载动画（旋转小图标），提示“思考中...”；回答生成后，加载动画消失，显示完整回复；网络异常时，提示“网络不佳，请稍后重试”，支持重新发送；

- 对话管理：支持清空当前会话历史（点击输入框右侧“清空对话”按钮），清空后提示“已清空对话历史”；支持复制单条消息（点击消息气泡右侧复制图标），复制成功有轻微提示；

- 输入辅助：输入框支持简单的自动补全（基于知识库中的文件名称、关键词），提升输入效率；支持输入校验，空输入、纯空格输入时，提示“请输入有效的问题”，无法发送；单轮输入最大支持2000字，超限提示“输入内容过长，请精简后再发送”。

### 3.5.3 聊天风格要求（严格贴合豆包）

- 语言风格：亲切、简洁、易懂，避免生硬的技术表述，回复语气与豆包一致，遇到模糊问题时，主动引导用户补充信息（例：“你可以具体说明要查询的文件名称哦”）；

- 视觉一致性：消息气泡、加载动画、按钮样式、字体、颜色均与豆包现有聊天功能保持一致，无差异化设计；

- 轻量化交互：聊天操作简单，无复杂步骤，支持快速切换聊天窗口与知识库页面，不影响文件上传、解析、导入等核心操作；

- 异常处理：无匹配知识库内容时，回复贴合豆包风格（例：“抱歉，暂时没有找到相关内容，你可以尝试更换关键词或检查知识库是否已导入哦”），不出现生硬的错误提示。

## 3.6 异常处理

- 网络异常：文件上传、解析、导入及聊天问答过程中，若网络中断，提示“网络异常，请检查网络后重试”，大文件支持断点续传，聊天消息发送失败可重新发送，避免数据丢失；

- 文件异常：文件损坏、格式不支持、大小超标等情况，均有明确提示，无法进行上传、解析操作；

- 服务异常：MinIO服务、Qdrant服务及聊天问答服务异常时，提示“服务暂时不可用，请稍后重试”，并记录异常日志，便于排查；

- 操作异常：用户误操作（如删除文件、删除向量、清空对话）时，弹出确认弹窗（例：“确定要删除该文件吗？删除后无法恢复”），避免误操作导致数据丢失；
