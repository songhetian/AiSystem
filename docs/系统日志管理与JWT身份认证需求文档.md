# 系统日志管理与JWT身份认证需求文档（V2.0）

**文档版本**：V2.0

**适用范围**：全系统操作日志、登录日志管理 + JWT统一身份验证

**核心目标**：日志数据可追溯、不可篡改，接口访问安全可控，异常场景可预判、可处理，满足审计合规与系统安全要求

**文档受众**：开发工程师、测试工程师、前端工程师、运维工程师、产品运营

# 一、文档说明

本文档基于资深产品视角，明确系统操作日志、登录日志的完整记录规则、展示规则（ID自动转换为真实姓名/名称）、辅助功能，补充JWT统一身份验证机制，并新增全场景异常判断，用于指导开发、测试、验收全流程，确保需求落地无歧义、系统运行无隐患，同时满足合规审计要求。

核心原则：日志仅可新增、查询，不可删除、不可编辑；JWT验证覆盖全接口，异常场景提前拦截、明确处理逻辑；所有ID展示均转换为对应真实名称，杜绝ID直接暴露。

# 二、核心功能需求

## 2.1 操作日志（不可删除、不可编辑）

### 2.1.1 记录字段（自动ID转名称展示）

所有日志由系统自动记录，用户无任何编辑/删除权限，数据库层面禁止删除、修改、更新操作；前端展示、日志导出时，所有关联ID（用户ID、平台ID、部门ID、店铺ID）均自动转换为对应真实名称，不显示任何ID原值。

|字段名称|展示内容|字段类型|说明|异常判断与处理|
|---|---|---|---|---|
|操作时间|年月日时分秒（YYYY-MM-DD HH:mm:ss）|datetime|系统自动生成，精确到秒，不可人工干预|异常：时间戳异常（为空、格式错误、早于系统当前时间）；处理：自动取系统当前时间，记录异常日志（标注“时间戳异常，已自动修正”），不影响主日志记录|
|操作人|用户真实姓名|字符串|根据操作人ID自动关联用户表，转换为真实姓名|异常1：操作人ID不存在/无效；处理：展示“未知用户”，日志正常记录，同时触发系统告警（通知管理员排查无效操作）；异常2：用户已删除但有操作记录；处理：展示“已删除用户（原ID：XXX）”，保留操作痕迹|
|操作模块|模块名称（如：用户管理、订单管理）|字符串|系统预设模块列表，自动匹配操作所属模块|异常：操作模块未匹配到预设列表；处理：展示“未知模块”，记录操作接口路径，触发告警，不影响日志留存|
|操作内容|具体操作描述（如：新增员工、修改订单状态）|字符串|自动拼接操作详情，清晰可追溯|异常：操作内容为空/过长（超过500字符）；处理：为空则填充“未获取到操作详情”，过长则截取前500字符，末尾标注“（内容已截取）”|
|操作IP|客户端真实IP地址|字符串|自动获取客户端公网IP，无法获取则记录内网IP|异常：IP获取失败（为空、格式错误）；处理：记录“IP获取失败”，同时记录客户端设备信息，不影响日志其他字段记录|
|操作结果|成功/失败|枚举|根据接口响应结果自动判断|异常：操作结果未返回（接口超时、中断）；处理：记录“操作异常（未返回结果）”，触发系统告警，排查接口问题|
|所属平台|平台真实名称|字符串|根据平台ID自动关联平台表，转换为平台名称|异常：平台ID不存在/无效；处理：展示“未知平台”，记录异常信息，触发告警，不影响日志留存|
|所属部门|部门真实名称|字符串|根据部门ID自动关联部门表，转换为部门名称|异常：部门ID不存在/已删除；处理：展示“未知部门/已删除部门”，保留操作痕迹，不影响日志有效性|
|所属店铺|店铺真实名称|字符串|根据店铺ID自动关联店铺表，转换为店铺名称（无店铺关联则显示“无”）|异常：店铺ID不存在/已注销；处理：展示“未知店铺/已注销店铺”，日志正常记录，不影响其他字段|
### 2.1.2 记录规则

- 触发场景：所有用户（管理员、普通用户、审计员）的增、删、改、查、导出、批量操作、配置修改等所有业务操作，均自动记录，无需人工干预；

- 权限限制：日志仅支持新增（系统自动）、查询，无任何删除、编辑、修改接口，数据库层面设置权限拦截，禁止手动修改日志数据；

- 失败记录：操作失败时，需在“操作内容”末尾补充失败原因（如：修改订单失败，原因：订单已取消），便于问题排查；

- 异常兜底：若系统出现临时故障（如数据库连接失败），日志需先缓存至本地，故障恢复后自动同步至数据库，确保无日志丢失。

## 2.2 登录日志（不可删除、不可编辑）

### 2.2.1 记录字段（自动ID转名称展示）

用户每次执行登录操作（无论成功、失败），系统均自动记录日志，永久留存，无任何修改、删除权限；前端展示、日志导出时，关联ID自动转换为真实名称，不显示ID原值。

|字段名称|展示内容|字段类型|说明|异常判断与处理|
|---|---|---|---|---|
|登录时间|年月日时分秒（YYYY-MM-DD HH:mm:ss）|datetime|系统自动生成，精确到秒|异常：时间戳异常（为空、格式错误）；处理：自动取系统当前时间，标注“时间异常，已修正”，不影响日志记录|
|登录人|用户真实姓名|字符串|根据登录账号/用户ID关联，转换为真实姓名|异常1：登录账号不存在/无效；处理：展示“未知账号”，记录登录账号（若有）；异常2：登录人已删除；处理：展示“已删除用户”，保留登录痕迹|
|登录IP|客户端真实IP地址|字符串|自动获取客户端公网IP|异常：IP获取失败；处理：记录“IP获取失败”，同时记录设备信息，不影响日志留存|
|登录设备|设备/浏览器信息（如：Chrome 120.0、Windows 11、iOS 17）|字符串|自动解析客户端User-Agent信息|异常：User-Agent解析失败/为空；处理：展示“未知设备”，日志正常记录，不影响其他字段|
|登录结果|成功/失败|枚举|根据登录校验结果自动判断|异常：登录过程中断（超时、网络异常）；处理：记录“登录异常（过程中断）”，触发告警，便于排查网络或系统问题|
|所属平台|平台真实名称|字符串|根据登录所属平台ID，转换为平台名称|异常：平台ID无效；处理：展示“未知平台”，记录异常信息，触发告警|
### 2.2.2 记录规则

- 触发场景：用户每次点击登录按钮（无论账号密码正确与否、验证码是否有效），均触发日志记录；

- 失败详情：登录失败时，需在“登录设备”字段末尾补充失败原因（如：密码错误、账号锁定、验证码过期）；

- 安全校验：同一账号1小时内连续5次登录失败，除记录日志外，触发账号临时锁定（15分钟），并推送告警给管理员；

- 异常兜底：系统故障导致登录日志无法即时写入数据库时，缓存至本地，故障恢复后自动同步，确保无登录行为遗漏。

## 2.3 日志辅助功能

### 2.3.1 多条件组合搜索

- 搜索区分：支持操作日志、登录日志分开搜索，默认展示操作日志，可手动切换；

- 筛选条件（均支持名称搜索，不支持ID搜索）：

    - 操作日志：操作人（姓名模糊匹配）、操作模块、操作时间范围、操作结果、所属平台、所属部门、所属店铺；

    - 登录日志：登录人（姓名模糊匹配）、登录时间范围、登录结果、登录设备（模糊匹配）、所属平台；

- 逻辑关系：多条件同时筛选时，逻辑为“并且（AND）”，确保搜索结果精准；

- 异常判断与处理：
        

    - 异常1：搜索条件为空（未选择任何条件、未输入关键词）；处理：默认展示最近30天的日志，分页展示；

    - 异常2：时间范围不合理（结束时间早于开始时间）；处理：自动修正为“开始时间=结束时间”，并提示用户“时间范围不合理，已自动修正”；

    - 异常3：搜索结果为空；处理：展示“无匹配日志”，同时提供重置搜索条件的入口；

    - 异常4：搜索关键词过长（超过50字符）；处理：自动截取前50字符，提示用户“关键词过长，已截取”。

### 2.3.2 日志导出

- 导出范围：仅导出当前搜索结果的日志数据，支持分页导出（导出当前页）、全量导出（导出所有匹配结果）；

- 导出格式：默认Excel（.xlsx），兼容Windows、Mac系统主流办公软件，导出文件命名格式：“操作日志_导出时间”/“登录日志_导出时间”；

- 展示规范：导出文件中所有字段均显示真实名称，不出现任何ID，字段顺序与前端列表一致，格式清晰可编辑；

- 异常判断与处理：
        

    - 异常1：导出数据量过大（超过10万条）；处理：提示用户“数据量过大，建议分批次导出”，同时提供“分批次导出”入口（按时间范围拆分）；

    - 异常2：导出失败（网络异常、服务器故障）；处理：提示用户“导出失败，请重试”，同时记录导出异常日志，便于管理员排查；

    - 异常3：无搜索结果时点击导出；处理：提示用户“无匹配日志，无法导出”；

    - 异常4：导出文件损坏；处理：支持重新导出，同时触发系统告警，排查导出功能异常。

### 2.3.3 分页查看

- 分页设置：默认分页展示，每页条数支持切换（10条/20条/50条/100条），默认20条/页；

- 操作支持：支持上一页、下一页、跳转到指定页码（输入页码后回车生效），页码范围自动限制（不可输入小于1、大于总页数的页码）；

- 详情查看：列表展示核心字段（操作/登录时间、操作/登录人、核心操作/登录结果、所属平台），点击单条日志可查看详情（展示所有字段）；

- 异常判断与处理：
        

    - 异常1：页码输入非法（非数字、小于1、大于总页数）；处理：自动修正为1页/最后一页，提示用户“页码非法，已自动修正”；

    - 异常2：分页加载失败（网络异常、服务器故障）；处理：提示用户“加载失败，请重试”，保留当前分页状态，重试后恢复；

    - 异常3：日志数据过多（超过100万条）；处理：分页加载正常，不卡顿，支持快速跳转到指定页码，同时优化查询性能。

## 2.4 JWT统一身份验证（项目必选，全接口覆盖）

核心目标：基于JWT（JSON Web Token）实现系统无状态身份认证，拦截未授权访问，保障接口安全，同时支持异常场景的快速处理，兼顾安全性与用户体验。

### 2.4.1 验证流程

1. 登录签发：用户登录成功后，服务端自动生成JWT令牌（Token），包含核心信息（用户ID、用户姓名、平台ID、角色权限、过期时间），通过接口返回给客户端；

2. 请求携带：客户端调用所有业务接口、日志接口（登录接口除外）时，必须在请求头Authorization中携带Token，格式：Bearer [Token]；

3. 服务端校验：服务端拦截所有接口请求，自动校验Token的存在性、有效性、过期时间、签名完整性；

4. 结果处理：校验通过则放行请求，正常返回数据；校验不通过则返回对应错误码及提示，拒绝请求；

5. 登出处理：用户主动登出后，Token立即加入黑名单，禁止重复使用；Token过期后，自动失效，需重新登录获取新Token。

### 2.4.2 技术规范

- Token包含信息：用户ID（隐藏存储，不暴露给前端）、用户姓名、平台ID、角色权限标识、过期时间、签名信息；

- 过期时间：默认2小时，支持Token刷新（用户操作过程中，自动刷新Token，延长有效期至2小时，避免频繁登录）；

- 签名加密：使用服务端唯一密钥（禁止泄露）进行签名，防止Token伪造、篡改；密钥定期更换（每3个月），更换时需保障存量有效Token正常使用至过期；

- 黑名单机制：用户登出、密码修改、账号锁定后，对应Token立即加入黑名单，黑名单定期清理（仅保留已过期Token），避免占用存储空间。

### 2.4.3 异常判断与处理（核心重点）

|异常场景|错误码|前端提示|服务端处理逻辑|补充说明|
|---|---|---|---|---|
|请求未携带Token|401|“请先登录，再进行操作”|直接拦截请求，不执行后续业务逻辑，记录拦截日志（标注“未携带Token”）|仅登录接口允许未携带Token|
|Token已过期|401|“登录已过期，请重新登录”|拦截请求，将Token加入黑名单，提示用户重新登录|支持自动刷新Token的场景，需提前5分钟刷新|
|Token签名无效（伪造、篡改）|401|“身份验证失败，请重新登录”|拦截请求，记录异常日志，触发系统告警（疑似恶意攻击），将Token加入黑名单|需排查客户端是否存在安全隐患|
|Token已被加入黑名单（登出、密码修改）|401|“登录状态已失效，请重新登录”|拦截请求，提示用户重新登录|密码修改后，所有关联Token均需失效|
|Token信息不完整（缺失核心字段）|401|“身份验证异常，请重新登录”|拦截请求，记录异常日志，触发告警，将Token加入黑名单|可能是Token生成异常或传输过程中损坏|
|Token中的用户/平台不存在（已删除）|401|“当前用户/平台已失效，请重新登录”|拦截请求，将Token加入黑名单，记录异常日志|用户/平台删除后，需同步清理关联Token|
|Token验证接口异常（服务端故障）|500|“系统异常，请稍后重试”|记录异常日志，触发紧急告警，尝试重试验证，失败则拦截请求|需优先修复验证接口，保障系统可用性|
### 2.4.4 适用范围

- 日志相关接口：操作日志查询、搜索、导出；登录日志查询、搜索、导出；

- 系统业务接口：所有用户操作、数据查询、配置修改、批量处理等接口；

- 权限相关接口：用户信息查询、角色管理、权限分配等接口；

- 例外接口：登录接口（获取Token）、忘记密码接口、验证码发送接口（无需Token验证，但需其他安全校验）。

# 三、非功能需求

## 3.1 数据安全性

- 日志安全：操作日志、登录日志仅支持新增（系统自动）、查询，任何角色（包括超级管理员）均无删除、编辑、修改权限；数据库层面设置字段不可更新、表不可删除，防止手动篡改；

- JWT安全：JWT密钥仅服务端持有，禁止泄露给客户端、前端人员；密钥定期更换，更换过程不影响存量有效Token使用；Token传输采用HTTPS加密，防止中途被窃取；

- 数据备份：日志数据每日自动备份，备份数据保留1年，支持故障恢复，确保日志数据不丢失；

- 异常告警：所有日志异常、JWT验证异常均触发系统告警，告警方式包括后台通知、邮件通知，管理员可及时排查。

## 3.2 性能要求

- 日志记录：异步执行，不影响主业务操作响应速度（主业务响应时间≤1秒，日志记录不增加额外延迟）；

- 查询性能：日志搜索、分页加载响应时间≤3秒；支持百万级日志数据存储与查询，无卡顿；

- 导出性能：单批次导出≤10万条数据时，响应时间≤10秒；超过10万条时，支持分批次导出，每批次响应时间≤10秒；

- JWT验证：接口验证响应时间≤500ms，不影响接口整体响应速度；支持高并发场景（≥1000QPS）下的稳定验证。

## 3.3 兼容性要求

- 日志导出：导出文件兼容Windows、Mac系统，支持Excel 2016及以上版本打开、编辑；

- JWT验证：兼容PC端、移动端（iOS/Android）、小程序、H5等所有客户端，确保不同终端请求均能正常校验；

- 浏览器兼容：日志查看、搜索、导出功能兼容Chrome、Edge、Firefox等主流浏览器（最新版本及前两个版本）。

## 3.4 可维护性要求

- 日志异常、JWT验证异常均有详细日志记录，便于管理员排查问题；

- JWT密钥更换、Token过期时间调整，支持后台配置，无需修改代码；

- 日志字段、搜索条件、导出格式支持灵活扩展，适配后续业务迭代。
