# 通知管理系统需求文档（PRD）

# 1. 文档概述

## 1.1 文档目的

本文档用于明确通知管理系统的全部功能需求、交互逻辑、异常处理及权限控制，为研发、测试、设计人员提供开发依据，确保系统落地符合业务预期，满足各模块联动、通知精准推送、权限分级管理的核心诉求。

## 1.2 核心目标

- 实现通知模板的灵活配置、管理，支持多变量、多场景适配；

- 完成通知自动发送与手动发送结合，覆盖各业务模块事件触发场景；

- 实现个人消息的精细化管理，支持自定义接收规则与操作；

- 严格控制权限分级，确保通知发送、接收、管理的安全性与合理性；

- 支持模块联动与拖拽交互，提升系统易用性与灵活性；

- 完善异常处理机制，保障系统稳定运行，降低异常对业务的影响。

## 1.3 适用范围

本文档适用于通知管理系统的产品设计、研发开发、测试验证、运维部署及相关业务人员学习参考。

# 2. 核心功能需求

## 2.1 通知模板管理

### 2.1.1 模板配置

- 支持新增5类核心通知模板：审批通知、考勤异常通知、订单通知、客服预警通知、接口监控异常通知，可拓展新增其他模板类型；

- 配置项要求：
        

    - 模板名称：必填，唯一，长度限制1-50字符，支持中英文、数字及特殊符号（@、_、-）；

    - 模板类型：必填，下拉选择（对应上述5类核心类型），不可自定义；

    - 通知内容：必填，支持富文本编辑，可插入模板变量（如${username}、${apiName}、${exceptionMsg}），变量插入后实时预览替换效果；

    - 关联信息：关联平台ID（必填）、部门ID（必填）、店铺ID（可选，关联后仅该店铺人员接收此模板通知）；

    - 通知方式：必填，可多选（系统内消息、短信、邮件），不同模板可配置不同组合，接口监控异常通知需额外配置提醒频率（如每10分钟提醒一次，直至异常解决，频率可自定义1-60分钟）。

### 2.1.2 模板管理操作

- 编辑模板：支持修改所有配置项（除模板类型外），修改后需保存版本记录，可回溯历史版本；

- 删除模板：仅管理员可删除，删除前需确认（提示“删除后不可恢复，且关联的联动规则将失效，是否确认删除？”），支持批量删除；

- 模板启用/禁用：所有拥有模板管理权限的用户可操作，禁用后该模板不再触发自动发送，手动发送时不可选择，禁用状态需在模板列表明显标注；

- 模板复制：支持复制现有模板，复制后自动生成“原模板名称_副本”，可直接编辑修改，提升配置效率；

- 模板变量管理：
        

    - 支持添加、编辑模板变量，每个变量需关联对应模块数据（如${username}关联用户模块、${apiName}关联接口监控模块）；

    - 新增接口监控专属变量：接口名称、异常字段、异常详情、监控时间，不可删除，可编辑变量显示名称；

    - 变量拖拽排序：在模板编辑页面，可拖拽模板变量调整其在通知内容中的显示顺序，拖拽后自动保存，预览时按排序展示变量替换效果。

## 2.2 消息发送管理

### 2.2.1 自动发送

- 模块联动触发：与审批流程、考勤排班、电商平台、客服质检、接口监控等模块联动，触发对应事件后自动匹配关联模板发送通知（如审批提交触发审批通知、接口监控异常触发接口监控异常通知）；

- 接收人分配规则：按平台、部门、店铺权限及模块关联关系分配，例如：
        

    - 审批通知：发送给审批人、申请人及对应部门管理员；

    - 接口监控异常通知：发送给对应平台+部门的管理员及接口负责人；

    - 关联店铺的模板：仅发送给该店铺所属人员。

- 接口监控异常通知特殊规则：按配置的提醒频率重复发送，直至异常解决，异常解决后自动停止提醒，发送记录中需标注“重复提醒”及提醒次数。

### 2.2.2 手动发送

- 操作权限：仅管理员及拥有对应模块权限的用户可操作，发送范围受自身平台、部门、店铺权限限制；

- 核心操作：
        

    - 选择通知模板（仅可选择启用状态的模板，且模板关联平台/部门需与当前用户权限匹配）；

    - 选择接收人：支持按平台、部门、店铺筛选，可多选，支持批量选择，筛选后显示接收人列表（含姓名、所属平台/部门/店铺、联系方式）；

    - 补充通知内容：可在模板原有内容基础上修改（不改变模板本身），支持添加临时变量或自定义文本；

    - 接口监控汇总通知：管理员及接口负责人可单独手动发送，选择时间段（如近1小时、近24小时）及指定监控接口，系统自动生成接口监控数据汇总内容（含接口名称、异常次数、异常详情），确认后发送。

- 批量发送限制：单次批量发送接收人上限100人，超过上限提示“单次发送人数不可超过100人，请分批次发送”。

### 2.2.3 发送记录

- 记录内容：保存所有通知发送记录（自动发送、手动发送），每条记录包含：发送时间、通知模板名称、发送方式、接收人（姓名+联系方式/账号）、发送状态（成功/失败）、关联平台/部门/店铺、关联模块事件（接口监控异常事件需额外显示接口名称、异常类型）；

- 操作功能：
        

    - 搜索：支持按发送时间、模板名称、发送状态、关联平台/部门/店铺、接收人搜索；

    - 导出：支持导出Excel格式，可选择导出全部记录或筛选后记录，导出内容与列表显示一致；

    - 详情查看：点击记录可查看完整通知内容、接收人明细（含每个接收人的发送状态及失败原因）。

## 2.3 我的消息管理

### 2.3.1 消息查看

- 消息筛选：按消息类型筛选（系统通知、审批通知、业务通知、接口监控通知），支持按已读/未读状态筛选；

- 列表显示：每条消息显示消息标题、消息内容（截取前50字符，hover显示完整内容）、发送时间、关联平台/部门/店铺、已读/未读状态（未读消息标红，显示未读标识）；

- 特殊跳转：接口监控相关消息点击后可直接跳转至接口监控详情页面，查看接口监控明细数据。

### 2.3.2 消息操作

- 标记已读/未读：支持单条标记、批量标记，未读消息点击后自动标记为已读；

- 删除消息：支持单条删除、批量删除，采用逻辑删除（删除后移入“已删除”列表，可保留30天，30天后自动彻底删除）；

- 收藏消息：支持单条收藏，收藏后可在“我的收藏”列表快速查看，支持取消收藏；

- 查看详情：点击消息查看完整内容，显示关联模块数据（如接口监控异常消息显示接口名称、异常字段、异常详情、监控时间；审批通知显示审批单号、审批状态、审批人）。

### 2.3.3 消息设置

- 接收方式自定义：可选择个人消息接收方式（仅系统内消息、仅短信、仅邮件、任意组合），默认全部勾选；

- 免打扰设置：可设置免打扰时间段（如22:00-次日08:00），免打扰期间不接收短信、邮件通知，系统内消息正常接收但不提示；

- 接口监控通知特殊设置：可单独设置接口监控异常通知的接收方式（与全局接收方式可不同）及免打扰规则（如免打扰期间仍接收紧急异常提醒）；

- 配置保存：所有设置实时保存，修改后立即生效，支持重置为默认配置。

### 2.3.4 消息列表拖拽自定义

- 列拖拽排序：可拖拽调整消息列表列的显示顺序（如将“关联店铺”列移至“发送时间”后）；

- 列显示/隐藏：可勾选/取消勾选列（如隐藏“发送方式”“接口名称”列），自定义列表显示内容；

- 配置保存：自定义配置自动保存，切换账号或刷新页面后保留个人设置，支持重置为默认列配置。

## 2.4 消息权限控制

### 2.4.1 发送权限

- 管理员：拥有所有模板的手动发送权限，可发送至任意平台、部门、店铺的用户；

- 普通用户：仅可发送自己所属平台、部门及关联店铺的通知，且仅可使用自己有权限的模块对应的模板；

- 接口监控通知特殊权限：仅管理员及接口负责人可手动发送，普通用户无操作权限。

### 2.4.2 接收权限

- 用户仅接收自己所属平台、部门、店铺及关联模块的通知，无权限的通知不展示、不推送（包括系统内消息、短信、邮件）；

- 接口监控通知：仅推送给对应平台+部门的管理员及接口负责人，其他用户无接收权限。

### 2.4.3 管理权限

- 管理员：可查看所有平台、部门、店铺的消息发送记录，可管理所有模板、联动规则；

- 普通用户：仅可查看自己接收的消息及自己发送的通知记录，不可查看其他用户的发送记录，不可管理模板及联动规则。

## 2.5 消息联动配置

### 2.5.1 模块联动

- 联动模块：与审批流程、考勤排班、电商平台、客服质检、知识库（接口监控）等所有核心业务模块联动；

- 触发场景：每个模块的关键事件（如审批提交/通过/驳回、考勤异常生成、订单生成/取消、客服差评提交、接口监控异常触发）均需触发对应通知模板发送。

### 2.5.2 联动规则

- 关联配置：可配置“模块事件-通知模板”的关联关系（一个事件可关联多个模板，一个模板可关联多个事件）；

- 接收人规则：配置每个联动规则的通知接收人（如接口监控异常事件关联的模板，接收人为平台管理员、部门管理员、接口负责人）；

- 关联范围：可关联具体平台、部门、店铺，不同平台+部门可配置不同的联动规则（如A平台的接口监控异常通知发送给A平台管理员，B平台的发送给B平台管理员）；

- 联动规则拖拽编排：可拖拽模块事件（含接口监控异常事件）与通知模板，建立关联关系；可拖拽调整联动规则的优先级（优先级高的规则先触发），拖拽后自动保存，优先级变更后立即生效。

# 3. 异常处理需求

异常处理核心原则：及时拦截异常、明确提示用户、记录异常日志、提供解决方案，确保异常不影响系统核心功能运行，减少对业务的干扰。

## 3.1 模板配置异常

- 异常场景1：模板名称重复

- 处理逻辑：点击保存时拦截，提示“模板名称已存在，请修改后重试”，不允许保存，焦点自动定位到模板名称输入框；

- 异常场景2：必填项未填写（模板名称、模板类型、通知内容、关联平台ID、部门ID、通知方式）

- 处理逻辑：点击保存时拦截，提示“请填写所有必填项（标*项）”，未填写项标红提示，不允许保存；

- 异常场景3：通知内容中插入未关联模块的变量

- 处理逻辑：点击保存时拦截，提示“存在未关联模块的变量，请编辑变量关联对应模块后重试”，标红异常变量；

- 异常场景4：接口监控异常模板未配置提醒频率

- 处理逻辑：点击保存时拦截，提示“接口监控异常模板需配置提醒频率，请补充后重试”，焦点定位到提醒频率配置项；

- 异常场景5：提醒频率设置超出范围（小于1分钟或大于60分钟）

- 处理逻辑：输入时实时校验，提示“提醒频率需在1-60分钟之间，请重新设置”，不允许输入超出范围的值。

## 3.2 消息发送异常

- 异常场景1：手动发送时未选择接收人

- 处理逻辑：点击发送时拦截，提示“请选择接收人后再发送”，不执行发送操作；

- 异常场景2：手动发送时接收人数量超出上限（超过100人）

- 处理逻辑：选择接收人后实时校验，提示“单次发送人数不可超过100人，请分批次发送”，不允许点击发送；

- 异常场景3：短信/邮件发送失败（如手机号格式错误、邮箱格式错误、短信通道异常、邮件服务器异常）

- 处理逻辑：
        

    - 单条接收人发送失败：发送记录中标注“失败”，鼠标hover显示失败原因（如“手机号格式错误”“邮件服务器连接失败”）；

    - 批量发送部分失败：成功的接收人正常推送，失败的记录单独标注，支持重新发送失败的接收人；

    - 全部发送失败：提示“通知发送失败，请检查发送方式配置（短信/邮件通道）及接收人信息后重试”，同时记录异常日志，通知运维人员；

    - 接口监控异常通知重复发送失败：连续3次发送失败后，停止重复提醒，标记“发送失败”，记录日志并通知管理员。

- 异常场景4：自动发送时无匹配的接收人

- 处理逻辑：不执行发送操作，记录异常日志（标注“无符合权限的接收人”），不提示用户，避免干扰业务流程；

- 异常场景5：手动发送时选择无权限的模板/接收范围

- 处理逻辑：拦截操作，提示“您无权限发送该模板/向该范围的用户发送通知，请检查权限后重试”，不执行发送操作。

## 3.3 拖拽操作异常

- 异常场景1：拖拽变量/列/联动规则时，拖拽动作异常（如拖拽后未触发保存、拖拽位置错误）

- 处理逻辑：拖拽后实时校验，若未保存成功，提示“拖拽配置保存失败，请重试”，自动恢复至拖拽前状态；若拖拽位置错误（如将变量拖拽至非内容区域），提示“拖拽位置无效，请重新拖拽”；

- 异常场景2：多用户同时拖拽同一模板的变量/同一联动规则

- 处理逻辑：采用乐观锁机制，后保存的用户会收到提示“该配置已被其他用户修改，请刷新页面后重新操作”，避免配置冲突。

## 3.4 权限异常

- 异常场景1：普通用户尝试访问管理员权限功能（如查看所有发送记录、删除其他用户创建的模板）

- 处理逻辑：拦截访问，提示“您无此操作权限，请联系管理员”，跳转至我的消息页面；

- 异常场景2：用户权限变更后，仍能访问原权限对应的功能

- 处理逻辑：权限变更后实时生效，刷新页面后隐藏无权限功能，若用户正在操作无权限功能，拦截并提示权限不足；

- 异常场景3：接口监控通知推送给无权限用户

- 处理逻辑：推送前校验接收人权限，过滤无权限用户，确保仅符合条件的管理员及接口负责人接收，同时记录校验日志。

## 3.5 系统异常

- 异常场景1：系统崩溃、接口调用失败

- 处理逻辑：
        

    - 用户端：提示“系统暂时异常，请稍后重试”，同时提供刷新按钮；

    - 系统端：自动记录异常日志（含异常时间、异常场景、异常原因），通知运维人员及时排查；

    - 数据保障：自动发送的通知在系统恢复后，若未发送成功，自动补发送（仅补发送一次），避免遗漏。

- 异常场景2：消息数据丢失、重复显示

- 处理逻辑：定期校验消息数据，若发现丢失，从备份数据中恢复；若发现重复，自动去重，同时记录异常日志，通知研发人员排查；

- 异常场景3：模板版本回溯失败

- 处理逻辑：提示“版本回溯失败，请重试”，记录失败日志，若多次失败，通知管理员手动处理。

## 3.6 其他异常

- 异常场景1：消息删除后，30天内未恢复，再次尝试恢复

- 处理逻辑：提示“该消息已彻底删除，无法恢复”；

- 异常场景2：导出发送记录时，数据量过大（超过10000条）

- 处理逻辑：提示“导出数据量过大，请筛选后分批导出”，限制单次导出最大数据量为10000条；

- 异常场景3：接口监控汇总通知未选择时间段/监控接口

- 处理逻辑：点击发送时拦截，提示“请选择时间段及监控接口后再发送”。

# 4. 交互需求补充

- 所有表单提交、操作确认（如删除、禁用）均需有二次确认提示，避免误操作；

- 模板编辑、联动规则配置页面，支持“保存草稿”功能，草稿可随时编辑、提交；

- 未读消息有明显标识（如标红、角标），系统内消息收到时，有弹窗提示（可在消息设置中关闭弹窗）；
