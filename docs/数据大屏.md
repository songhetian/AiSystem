# 模块9：数据大屏（Dashboard）【可视化统计】需求文档（PRD）

# 1. 文档概述

## 1.1 文档目的

本文档明确数据大屏（Dashboard）模块的功能需求、异常处理规则、交互逻辑及约束条件，为研发、测试、设计等相关人员提供开发依据，确保模块功能符合业务预期，满足各角色对数据可视化统计、监控及分析的需求。

## 1.2 适用范围

本文档适用于数据大屏模块的研发、测试、部署及后期迭代优化，覆盖产品经理、研发工程师、测试工程师、UI/UX设计师及相关业务负责人。

## 1.3 核心目标

1. 提供多场景大屏模板，支持自定义配置，实现全平台、多维度数据的可视化展示；

2. 新增接口监控大屏，实现核心接口数据实时监控、异常预警，填补接口监控可视化空白；

3. 支持多条件筛选、数据钻取，满足不同角色对细分数据的查询需求；

4. 完善异常处理机制，确保大屏数据展示、操作交互、预警提醒的稳定性和可靠性；

5. 支持大屏分享、定时刷新，提升数据传递效率和实时性。

# 2. 功能需求

## 2.1 大屏模板管理

### 2.1.1 模板配置

1. 支持新增大屏模板，涵盖以下预设模板类型：全局总览、电商运营、人事管理、客服质检、接口监控；

2. 配置项包括：模板名称（必填，唯一）、模板描述（选填，说明模板用途及适用场景）、关联平台ID（必填，支持多选）、部门ID（必填，支持多选），可按“平台+部门”组合配置专属模板，确保不同平台、部门只能查看对应权限的模板；

3. 模板配置完成后，需提交保存，生成唯一模板ID，用于后续管理和调用。

### 2.1.2 模板组件

1. 所有模板默认包含基础固定统计组件：数据总览卡片（展示核心指标数值）、柱状图（用于数据对比）、饼图（用于占比分析）、折线图（用于趋势分析）；

2. 新增接口监控组件，核心展示内容：核心接口监控数据（平均响应时间、调用成功率、异常次数）、异常提醒标识；

3. 支持自定义组件布局，可调整组件的位置、大小、显示顺序，组件数据需严格关联“平台+部门+店铺”，确保数据权限隔离；

4. 组件支持单独配置数据源，确保不同模板、不同组件展示的数据精准匹配业务需求。

### 2.1.3 模板管理操作

1. 编辑模板：支持修改模板的配置信息（名称、描述、关联平台/部门）、组件布局及组件数据源，编辑后需保存生效，历史配置可追溯；

2. 删除模板：支持删除无用模板，删除前需弹出确认提示（提示“删除后不可恢复，请确认”），已启用的模板需先禁用才可删除；

3. 模板启用/禁用：启用后的模板可在大屏列表中查看并使用，禁用后的模板隐藏，不可查看、使用，但保留模板数据，可重新启用；

4. 模板复制：支持快速复制现有模板，复制后生成新模板（默认名称为“原模板名称+副本”），可直接编辑修改，提升模板创建效率；

5. 模板权限控制：按角色分配模板查看权限，不同角色仅能查看自身权限范围内的模板，权限分配需关联平台、部门权限，确保数据安全。

## 2.2 数据可视化展示

### 2.2.1 全局总览大屏

1. 核心展示数据：员工总数、部门总数、店铺总数、订单总额、报销总额、会话总量、核心接口调用成功率；

2. 支持筛选功能：可按平台、部门筛选查看细分数据，筛选后所有组件数据实时同步更新；

3. 数据展示要求：核心指标以卡片形式突出显示，辅助数据以图表（柱状图、折线图）形式展示，确保数据直观易懂。

### 2.2.2 电商运营大屏

1. 数据维度：按平台、部门、店铺展示电商核心数据，包括商品总数、上架商品数、订单数量、订单总额、退款金额、客户满意度；

2. 图表生成：自动生成数据趋势图（展示数据随时间变化趋势）、对比图（展示不同平台/部门/店铺数据对比）；

3. 时间筛选：支持按时间段筛选数据，可选范围：日、周、月、年，也可自定义时间段（起止日期），筛选后图表及数值实时更新。

### 2.2.3 人事管理大屏

1. 数据维度：按平台、部门展示人事核心数据，包括在职员工数、新入职员工数、离职员工数、考勤正常率、请假/加班次数；

2. 图表生成：自动生成统计图表（柱状图、饼图、折线图），清晰展示人事数据分布及变化趋势；

3. 时间筛选：支持按时间段筛选数据（日/周/月/年/自定义），筛选后数据实时更新。

### 2.2.4 客服质检大屏

1. 数据维度：按平台、部门、店铺展示客服核心数据，包括在线客服数、接会话量、平均响应时长、质检合格率、客户满意度；

2. 实时性要求：数据实时更新，更新频率与大屏定时刷新频率一致；

3. 异常预警：支持质检相关异常预警（如质检合格率低于阈值），预警时对应组件高亮显示。

### 2.2.5 接口监控大屏（新增）

1. 核心展示数据：集中展示所有监控接口的核心指标，包括平均响应时间、调用成功率、异常次数；

2. 分组展示：按平台、部门、店铺分组展示接口数据，便于区分不同维度的接口运行状态；

3. 异常提醒：异常接口高亮显示（如红色边框、背景色），直观区分正常/异常接口；

4. 数据钻取：点击异常接口或对应组件，可钻取查看详细监控数据（如接口调用明细、异常原因）及趋势图，支持多级钻取。

## 2.3 数据筛选与钻取

### 2.3.1 多条件筛选

1. 基础筛选条件：支持按平台、部门、店铺、时间段（自定义起止日期）筛选大屏所有组件数据，筛选操作后实时更新所有组件数据，无延迟；

2. 专项筛选：接口监控组件额外支持按接口名称、监控字段（如响应时间、调用成功率）筛选，精准定位目标接口数据；

3. 筛选记忆：保存用户最近一次的筛选条件，下次进入大屏时自动加载，可手动清除筛选条件（重置筛选）。

### 2.3.2 数据钻取

1. 钻取触发：点击大屏任意组件（如订单总额柱状图、接口响应时间折线图、数据卡片），可触发钻取操作；

2. 钻取内容：钻取后展示对应指标的细分数据（如各店铺订单明细、接口不同时间节点的监控数据、员工考勤明细）；

3. 多级钻取：支持多级钻取（如点击订单总额→各部门订单→各店铺订单→订单明细），钻取深度可配置；

4. 权限控制：钻取数据严格关联用户的平台、部门、店铺权限，无权限的细分数据不可查看，提示“无权限访问”。

## 2.4 大屏配置与分享

### 2.4.1 自定义配置

1. 组件布局配置：支持拖拽调整大屏组件的大小、位置，支持组件对齐（左对齐、右对齐、居中对齐）、均匀分布（横向均匀、纵向均匀），拖拽后自动保存个人配置；

2. 组件样式配置：支持修改组件的颜色（背景色、字体色、边框色）、字体（字体类型、字体大小），保存后仅对当前用户生效，不同用户可拥有不同配置；

3. 接口监控组件专项配置：支持自定义选择展示的监控接口及监控字段，支持设置异常预警阈值（如响应时间阈值、异常次数阈值），配置后自动保存。

### 2.4.2 大屏分享

1. 分享链接生成：支持生成大屏分享链接，链接有效期可配置（如1小时、1天、7天、永久），生成后可复制分享；

2. 权限控制：分享链接仅对拥有对应平台、部门、店铺权限的用户可见，无权限用户点击链接后提示“无权限访问，请联系管理员获取权限”；

3. 分享管理：支持查看个人生成的分享链接列表，可手动失效已生成的链接（失效后链接无法访问）。

### 2.4.3 定时刷新

1. 刷新频率配置：支持用户自定义大屏数据刷新频率，可选范围：1分钟、5分钟、10分钟，默认刷新频率为5分钟；

2. 实时同步：按配置的频率自动刷新大屏所有数据（含接口监控数据），确保数据与实际业务数据一致；

3. 刷新提示：刷新过程中显示“正在刷新数据...”提示，刷新完成后自动隐藏；刷新失败时显示明确的错误提示（如“数据刷新失败，请检查网络连接或联系技术支持”）。

## 2.5 异常预警

### 2.5.1 预警配置

1. 预警阈值设置：支持设置核心数据的预警阈值，涵盖以下场景：订单退款率、质检合格率、接口响应时间、接口异常次数、考勤正常率等；

2. 权限关联：预警阈值可按“平台+部门+店铺”组合设置，不同组合可配置不同阈值（如A部门接口响应时间阈值为500ms，B部门为800ms）；

3. 阈值管理：支持编辑、删除已设置的预警阈值，新增、修改阈值后需保存生效，历史阈值配置可追溯。

### 2.5.2 预警提醒

1. 大屏提醒：当数据达到预警阈值时，对应大屏组件高亮显示（如红色边框、闪烁提示、背景色变化），直观提醒用户；

2. 系统消息提醒：自动发送系统消息给对应管理员（按平台、部门关联管理员），提醒信息需包含：预警时间、预警类型、预警数据、关联平台/部门/店铺，接口监控异常需额外标注接口名称、异常字段及异常数值；

3. 提醒优先级：接口监控异常、订单退款率超标等紧急预警，提醒消息标为“紧急”，优先推送；其他预警标为“普通”，正常推送。

### 2.5.3 预警记录

1. 记录保存：保存所有预警记录，记录内容包括：预警时间、预警类型、预警数据（阈值、实际数值）、关联平台/部门/店铺、处理状态（未处理/已处理）、处理人、处理时间；

2. 筛选与搜索：支持按预警类型（接口监控、订单、质检、人事等）、处理状态、时间范围筛选预警记录，支持按预警关键词（如接口名称、部门名称）搜索；

3. 导出功能：支持导出预警记录，导出格式为Excel，导出内容与当前筛选后的记录一致；

4. 处理操作：管理员可标记预警记录为“已处理”，并填写处理备注（选填），处理后记录状态更新，备注信息同步保存。

## 2.6 拖拽功能

1. 大屏组件拖拽布局：在大屏配置页面，支持拖拽组件调整位置、大小，支持组件对齐（左、右、居中）、均匀分布（横向、纵向），拖拽操作后自动保存配置，无需手动提交；

2. 组件排序拖拽：支持拖拽大屏组件调整展示层级（上下顺序），层级高的组件显示在上方，拖拽后自动保存排序配置；

3. 筛选条件面板拖拽自定义：支持拖拽调整筛选条件的显示顺序，支持设置筛选条件的显示/隐藏，保存个人自定义筛选面板配置，下次进入自动加载；

4. 接口监控组件拖拽配置：在大屏配置页面，可拖拽接口监控组件至指定位置，调整组件大小，配置组件展示的监控接口及字段，拖拽后自动保存配置。

# 3. 异常处理需求

## 3.1 数据异常处理

### 3.1.1 数据加载异常

1. 场景：大屏加载时，数据请求失败（网络异常、接口报错、数据库异常）；

2. 处理逻辑：显示明确的错误提示（如“数据加载失败，请检查网络连接或联系技术支持”），提供“重新加载”按钮，用户点击后重新请求数据；

3. 兜底方案：若多次重新加载仍失败，显示默认空数据页面（提示“暂无数据可用”），不展示错误堆栈，避免用户看到技术细节。

### 3.1.2 数据缺失/异常值处理

1. 场景：部分指标数据缺失、数值异常（如负数、超出合理范围）；

2. 处理逻辑：缺失数据显示“--”，异常数值标注“异常”，并鼠标悬浮提示“数据异常，请联系管理员核实”；

3. 异常上报：系统自动记录数据异常日志（含异常指标、异常数值、发生时间、关联平台/部门），同步推送消息给技术人员，便于排查问题。

### 3.1.3 定时刷新异常

1. 场景：按配置频率刷新数据时，刷新失败（网络中断、接口超时）；

2. 处理逻辑：显示错误提示（如“数据刷新失败，将在5分钟后重新尝试”），无需用户手动操作，系统自动重试刷新；

3. 重试机制：连续3次刷新失败后，停止自动重试，显示“刷新多次失败，请检查网络或联系技术支持”，提供“手动刷新”按钮。

## 3.2 操作异常处理

### 3.2.1 模板操作异常

1. 场景：编辑/删除/复制模板时，操作失败（权限不足、模板被占用、系统异常）；

2. 处理逻辑：显示对应错误提示（如“权限不足，无法编辑该模板”“该模板正在被使用，无法删除”），明确操作失败原因，引导用户进行正确操作；

3. 特殊处理：复制模板时，若原模板数据异常，复制失败，提示“原模板数据异常，无法复制，请先核实原模板”。

### 3.2.2 拖拽操作异常

1. 场景：拖拽组件时，拖拽失败（组件重叠、超出大屏边界、系统卡顿）；

2. 处理逻辑：拖拽时若组件超出边界，自动吸附至大屏内；若组件重叠，显示提示“组件不可重叠，请调整位置”；拖拽卡顿/失败时，提示“操作失败，请重试”，拖拽操作不保存，恢复至拖拽前状态；

3. 兜底方案：拖拽过程中浏览器崩溃，重新打开大屏后，加载最近一次保存的拖拽配置，避免用户操作丢失。

### 3.2.3 筛选与钻取异常

1. 场景：筛选时无匹配数据、钻取时无权限/无细分数据；

2. 处理逻辑：筛选无匹配数据时，显示“暂无符合条件的数据”；钻取无权限时，显示“无权限访问该细分数据，请联系管理员”；钻取无细分数据时，显示“暂无细分数据可用”；

3. 引导操作：无数据时，提供“重置筛选”按钮（筛选场景）、“返回上一级”按钮（钻取场景），引导用户调整操作。

### 3.2.4 分享操作异常

1. 场景：生成分享链接失败、分享链接失效/被篡改；

2. 处理逻辑：生成链接失败时，提示“分享链接生成失败，请重试”；用户点击失效/被篡改的链接时，提示“该分享链接已失效或被篡改，请联系分享人重新生成”；

3. 安全处理：若检测到分享链接被非法篡改，自动标记链接为失效，同步记录异常日志，推送消息给管理员。

## 3.3 预警异常处理

### 3.3.1 预警阈值配置异常

1. 场景：设置预警阈值时，输入无效值（非数字、负数、超出合理范围）；

2. 处理逻辑：实时校验输入值，无效值时提示“请输入有效的预警阈值（正数，范围：XXX-XXX）”，无法保存配置，引导用户修正；

3. 默认阈值：若用户未设置阈值，系统提供默认阈值（可配置），确保预警功能正常运行。

### 3.3.2 预警提醒异常

1. 场景：预警触发后，提醒消息发送失败（系统异常、管理员账号异常）；

2. 处理逻辑：系统自动记录提醒失败日志（含预警信息、失败原因），重试发送（间隔5分钟，重试3次）；重试失败后，推送消息给技术人员，手动处理；

3. 兜底方案：提醒消息发送失败时，大屏组件仍保持高亮预警，确保用户在大屏端能看到异常。

### 3.3.3 预警记录异常

1. 场景：预警记录保存失败、导出失败；

2. 处理逻辑：保存失败时，提示“预警记录保存失败，请重试”，自动重试保存；导出失败时，提示“导出失败，请检查网络或重试”，支持重新导出；

3. 数据备份：预警记录自动备份，防止数据丢失，备份周期为1个月，可追溯历史记录。

## 3.4 系统异常处理

1. 场景：系统崩溃、页面卡死、浏览器兼容问题；

2. 处理逻辑：页面卡死时，显示“页面无响应，请刷新页面重试”；系统崩溃时，自动跳转至系统异常页面（提示“系统异常，请联系技术支持”）；浏览器兼容问题时，提示“当前浏览器不兼容，请使用Chrome、Edge等主流浏览器”；

3. 异常日志：所有系统异常自动记录日志（含异常场景、发生时间、用户信息），便于技术人员排查问题，日志保存周期为3个月。

# 4. 约束与限制
