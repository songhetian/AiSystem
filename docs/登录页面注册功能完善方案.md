# 登录页面注册功能完善方案

# 一、功能整体概述

在现有登录页面新增注册入口及完整注册流程，用户通过注册入口填写必要信息完成注册申请，提交后由管理员在审核页面进行审核，审核通过后方可使用注册账号登录系统；其中部门选择需通过单独接口获取所有部门数据，确保部门信息实时同步、准确无误，全程保障流程流畅性、数据安全性及操作便捷性。

# 二、登录页面注册入口设计

## 2.1 入口位置与样式

1.  入口位置：在登录页面“登录”按钮下方，添加“还没有账号？立即注册”文字链接，文字颜色与页面整体风格统一，hover状态有明显视觉反馈（如颜色加深、下划线），便于用户快速找到。

2.  跳转逻辑：点击注册链接后，跳转至注册表单页面（可内嵌在登录页面弹窗，也可跳转至独立注册页，推荐弹窗形式，减少页面跳转，提升用户体验）；弹窗/页面顶部显示“用户注册”标题，底部提供“返回登录”链接，方便用户切换。

## 2.2 注册表单设计（核心内容）

注册表单需包含以下必填项（标注*），表单布局清晰，字段提示明确，提交前进行前端校验，具体字段如下：

- *姓名：输入框，输入限制为2-10个汉字（禁止特殊字符、数字）， placeholder提示“请输入真实姓名”，校验不通过提示“请输入2-10个有效汉字姓名”。

- *手机号：输入框，输入限制为11位纯数字， placeholder提示“请输入手机号”，校验规则：需符合中国大陆手机号格式（13/14/15/17/18/19开头），校验不通过提示“请输入有效的11位手机号”；同时添加手机号唯一性校验（调用后端接口，判断该手机号是否已被注册），若已注册提示“该手机号已注册，请直接登录或找回密码”。

- *部门选择：下拉选择框， placeholder提示“请选择所属部门”，下拉选项数据通过单独接口获取（接口详情见第三部分），禁止手动输入，仅可选择下拉列表中的部门；若接口调用失败，显示“部门数据加载失败，请刷新页面重试”提示，同时禁用注册提交按钮。

- 密码：输入框，密码类型（隐藏输入），输入限制为8-16位，包含字母、数字、特殊字符（至少两种）， placeholder提示“请设置登录密码”，校验不通过提示“密码需8-16位，包含字母、数字、特殊字符中的至少两种”。

- 确认密码：输入框，密码类型（隐藏输入）， placeholder提示“请确认密码”，校验规则：与密码输入内容一致，校验不通过提示“两次密码输入不一致，请重新输入”。

- 验证码：输入框+获取验证码按钮，验证码由后端生成，发送至填写的手机号，有效时长5分钟；点击“获取验证码”后，按钮置灰（倒计时60秒），倒计时结束后恢复可点击状态；校验不通过提示“验证码错误或已过期，请重新获取”。

- 协议勾选：勾选框+“我已阅读并同意《用户注册协议》《隐私政策》”文字，未勾选时禁用提交按钮，勾选后才可提交注册申请。

表单底部设置“提交注册”按钮，按钮默认置灰（未满足所有必填项、未勾选协议时），满足所有校验条件后变为可点击状态；提交过程中显示加载动画，禁止重复点击。

# 四、注册提交与后端处理流程

## 4.1 前端提交逻辑

用户完成表单填写并通过所有前端校验后，点击“提交注册”按钮，前端将表单数据（姓名、手机号、部门ID、密码（加密后）、验证码）以JSON格式提交至注册接口，提交过程中显示“注册中，请稍候...”加载提示，禁止重复点击；提交成功/失败后，显示对应提示信息。

## 4.2 注册接口设计（简要）

请求方式：POST；请求地址：/api/user/register；

请求参数：{"userName":"姓名","phone":"手机号","deptId":"选择的部门ID","password":"加密后的密码","code":"验证码"}；

返回结果：

- 成功：{"code":200,"message":"注册申请提交成功，请等待管理员审核，审核通过后即可登录"}；

- 失败：{"code":400,"message":"具体失败原因（如验证码错误、手机号已注册、部门ID无效等）"}。

## 4.3 后端数据处理

1.  数据校验：后端接收前端提交的注册数据后，再次进行校验（避免前端校验被绕过），包括手机号格式、部门ID有效性、验证码正确性、密码格式等，校验失败返回对应错误信息；

2.  数据存储：校验通过后，将用户信息存入用户表，设置用户状态为“待审核”（状态值可设为0，审核通过为1，审核拒绝为2），同时关联对应的部门ID（与部门表关联），密码需进行加密处理（如MD5、SHA256），禁止明文存储；

3.  数据关联：将该注册申请同步至审核表，关联用户ID、注册时间、部门信息，便于管理员查看审核。

# 五、管理员审核流程

## 5.1 审核页面展示内容

管理员登录系统后，进入“用户审核”页面（单独菜单入口），页面展示所有“待审核”状态的注册申请，支持分页、搜索（按姓名、手机号、部门搜索），列表展示以下信息：

- 序号、姓名、手机号、所属部门、注册时间、操作（审核通过、审核拒绝）；

- 点击某条申请，可查看该用户的完整注册信息（姓名、手机号、部门、注册时间），便于管理员核实信息。

## 5.2 审核操作逻辑

1.  审核通过：管理员点击“审核通过”按钮，后端将该用户的状态从“待审核”改为“审核通过”，同时更新审核时间、审核人信息；更新后，该用户可使用注册的手机号和密码登录系统，审核页面不再显示该条申请（可在“已审核”列表中查看）。

2.  审核拒绝：管理员点击“审核拒绝”按钮，弹出输入框，要求填写拒绝原因（必填），提交后，后端将该用户的状态改为“审核拒绝”，更新审核时间、审核人、拒绝原因；同时，系统自动向该用户的手机号发送拒绝通知（内容包含拒绝原因，如“您的注册申请未通过审核，原因：XXX，请核对信息后重新注册”），审核页面不再显示该条申请（可在“已拒绝”列表中查看）。

3.  批量操作（可选）：支持批量审核通过、批量拒绝，提升管理员审核效率；批量拒绝时，需统一填写拒绝原因。

## 5.3 审核状态同步

1.  管理员审核完成后，用户状态实时更新，确保未审核用户无法登录，审核通过用户可正常登录，审核拒绝用户无法登录；

2.  审核页面实时刷新（可设置自动刷新，每30秒刷新一次，或手动刷新），确保管理员能及时看到最新的待审核申请。

# 六、登录校验逻辑调整

在现有登录校验逻辑基础上，增加用户状态校验，具体规则如下：

- 用户输入手机号和密码后，后端首先校验手机号和密码是否匹配；

- 若匹配，进一步校验用户状态：

- - 状态为“审核通过”：校验通过，允许登录，跳转至系统首页；

- - 状态为“待审核”：提示“您的注册申请正在审核中，请耐心等待管理员审核”，拒绝登录；

- - 状态为“审核拒绝”：提示“您的注册申请未通过审核，原因：XXX，请核对信息后重新注册”（拒绝原因从后端获取），拒绝登录；

- 若手机号和密码不匹配，提示“手机号或密码错误，请重新输入”。

# 七、异常场景与容错处理

- 场景1：用户注册后，管理员未审核，用户尝试登录 → 提示待审核，禁止登录；

- 场景2：用户注册时，部门接口调用失败，无法选择部门 → 禁止提交注册，提示加载失败，引导刷新；

- 场景3：管理员审核时，用户信息已被删除 → 提示“该用户信息已失效，无法审核”；

- 场景4：用户注册后，手机号被他人占用（后端校验遗漏） → 后端定期校验，发现重复手机号，自动将后注册的用户状态改为“审核拒绝”，并通知用户；

- 场景5：密码加密异常 → 后端校验密码加密结果，加密失败则返回注册失败，提示“注册失败，请重试”。
