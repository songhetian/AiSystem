# 前端运行时配置说明

## 问题背景

Vite的环境变量（`VITE_*`）在构建时就被固定到代码中了，无法在运行时动态修改。这导致：
- 修改`.env`文件后需要重新构建镜像才能生效
- 无法灵活配置不同环境的API地址
- 端口或地址变化时需要修改代码

## 解决方案

使用**运行时配置文件**，在容器启动时从环境变量动态生成配置，无需重新构建镜像。

### 工作原理

1. **构建时**：
   - `public/config.js` 包含占位符 `__API_BASE_URL__`
   - 构建后复制到 `dist/config.js`

2. **运行时**：
   - `entrypoint.sh` 脚本在容器启动时执行
   - 从环境变量 `VITE_API_BASE_URL` 读取实际值
   - 替换 `dist/config.js` 中的占位符
   - 启动应用服务器

3. **前端加载**：
   - HTML中引入 `/config.js`
   - `request.ts` 从 `window.APP_CONFIG.apiBaseUrl` 读取配置
   - 优先级：运行时配置 > 构建时环境变量 > 默认值

### 配置优先级

```
window.APP_CONFIG.apiBaseUrl (最高)
  ↓
process.env.VITE_API_BASE_URL
  ↓
/api/v1 (默认值)
```

## 使用方法

### 1. 修改API地址（无需重新构建）

编辑 `.env` 或 `docker-compose.yml`：

```bash
# .env
VITE_API_BASE_URL=http://localhost:3000/api/v1
```

或在 `docker-compose.yml` 中：

```yaml
environment:
  - VITE_API_BASE_URL=http://localhost:3000/api/v1
```

然后重启容器：

```bash
docker compose restart frontend
```

### 2. 本地开发

修改 `frontend/public/config.js`：

```javascript
window.APP_CONFIG = {
  apiBaseUrl: 'http://localhost:3000/api/v1',
};
```

保存后刷新浏览器即可生效。

### 3. 生产环境

在 `docker-compose.yml` 中设置：

```yaml
environment:
  - VITE_API_BASE_URL=https://api.yourdomain.com/api/v1
```

或使用Nginx反向代理（推荐）：

```yaml
environment:
  - VITE_API_BASE_URL=/api/v1  # 相对路径，通过Nginx代理
```

## 文件说明

### `frontend/public/config.js`
运行时配置模板，包含占位符。

### `frontend/entrypoint.sh`
容器启动脚本，负责：
- 从环境变量读取配置
- 替换占位符
- 启动应用

### `frontend/src/utils/request.ts`
HTTP请求工具，从 `window.APP_CONFIG` 读取API地址。

### `frontend/.umirc.ts`
Umi配置，在HTML中引入 `config.js`。

## 优势

✅ **无需重新构建镜像** - 修改环境变量后重启容器即可  
✅ **灵活配置** - 支持不同环境使用不同配置  
✅ **向后兼容** - 仍然支持构建时环境变量  
✅ **易于维护** - 配置集中管理，清晰明了  

## 注意事项

1. **首次使用需要重新构建镜像**（因为添加了entrypoint.sh）
2. **后续修改配置只需重启容器**
3. **本地开发可以直接修改 `public/config.js`**
4. **生产环境建议使用Nginx反向代理**

## 故障排查

### 问题：修改环境变量后不生效

**解决**：
```bash
# 1. 重启容器
docker compose restart frontend

# 2. 查看容器日志，确认配置已生成
docker compose logs frontend | grep "运行时配置"

# 3. 进入容器检查配置文件
docker exec -it frontend-service cat /app/dist/config.js
```

### 问题：API请求404

**解决**：
```bash
# 1. 检查后端服务是否正常
curl http://localhost:3000/api/v1/health

# 2. 检查前端配置
# 浏览器控制台执行：
console.log(window.APP_CONFIG)

# 3. 检查请求地址
# 浏览器Network面板查看实际请求的URL
```

### 问题：Docker镜像源问题无法构建

**临时解决**：
```bash
# 1. 修改Dockerfile，使用国内镜像源
# 在Dockerfile开头添加：
# RUN npm config set registry https://registry.npmmirror.com

# 2. 或者使用已有镜像，只挂载配置文件
# 在docker-compose.yml中添加volume：
# - ./frontend/public/config.js:/app/dist/config.js
```

## 扩展配置

如需添加更多运行时配置，编辑 `public/config.js`：

```javascript
window.APP_CONFIG = {
  apiBaseUrl: '__API_BASE_URL__',
  version: '__APP_VERSION__',
  environment: '__NODE_ENV__',
  // 添加更多配置...
};
```

然后在 `entrypoint.sh` 中添加替换逻辑：

```bash
sed -i "s|__APP_VERSION__|$APP_VERSION|g" "$CONFIG_FILE"
sed -i "s|__NODE_ENV__|$NODE_ENV|g" "$CONFIG_FILE"
```
